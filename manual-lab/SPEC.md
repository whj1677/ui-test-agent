# 巡维演练台：冻结合成业务规格 v1

本文件由 Codex 在 Kimi 实现前确定，是本次练习的判定依据，不代表真实业务规则。

## 任务状态卡

- 目标：复杂网站及配套人工测试包就绪，用户自己运行 UI Test Agent。
- 交付：独立站点、18有效/4待澄清/2已知缺陷用例、手册、独立夹具核验。
- 不做：更改 Agent、原有验收集、旧任务、4179进程、真实模型调用、互联网部署。
- 权限：仅本次合成资料给 Kimi 编写 UI/用例。浏览器写入只限练习命名空间。
- 停止：站点及用例实际核验并交接；不把 Agent 测试结果提前判为通过。

## 全局契约

站点名「巡维演练台」，本机 http://127.0.0.1:4196 。首次显示「进入演示」按钮，不要账号密码，点击后 `/overview`，h1「运营总览」。登录标记使用 localStorage `complex-lab-v1-auth`，工单使用 `complex-lab-v1-orders`；此标记无鉴权安全含义，仅模拟登录。全新上下文或人工点击「重置演练数据」重建种子数据，不触碰其他键。重置按钮只在总览页、需确认，不能自动重置用户任务。

侧栏可展开「运营中心」，其子项「资产设备」(`/assets`, h1「资产设备」)、「电价管理」(`/tariffs`, h1「电价管理」)、「工单中心」(`/work-orders`, h1「工单中心」)、「审计日志」(`/audit`, h1「审计日志」)。history API/后退可用，直达路由需模拟登录。布局是左侧导航+顶部上下文+统计卡+查询栏+表格。离线、零外部资源、零依赖、单文件HTML/CSS/JS。无视频轮播、无页面自动滚动。系统字体，深蓝#1E40AF、白卡、浅灰背景，普通文本对比≥4.5，焦点明显，375px可操作，表格自己的横向滚动，不撑宽整页。

所有表单输入有可访问label，行内同名按钮保留而且行身份清楚。弹窗用原生dialog/showModal，命名、Escape、取消、焦点归还正确。嵌套弹窗仅顶层可交互；关闭顶层后父层仍在。控件为真实UI，不在DOM藏测试答案、无自动化专用题目按钮。异步请求用本地定时器模拟600ms，界面明确加载、错误、重试状态。禁止外部fetch/网络，避免页面切换后旧异步回调污染新页面。

详情抽屉dialog名「设备详情」，内容h2必须为当前设备编号（如D009），明确名称园区功率。tab「基本信息」「运行参数」「维护记录」。基本信息有「读取说明」开嵌套dialog名「读取说明」，内容「读数每60秒更新」，「关闭说明」仅关闭说明；父抽屉「关闭详情」。运行参数：每台「巡检周期」7天、「额定频率」50 Hz（D004故意显示52 Hz，属BUG02）。按钮「加载遥测」第一次后显示「遥测读取失败，请重试」及「重试」，第二次600ms后显示当前设备额定功率的90%作为「实时功率」（D009=180 kW）。关闭抽屉再开重置遥测尝试。

维护记录：D009固定记录MR091 2026-09-10 日常巡检 完成；MR092 2026-09-12 传感器校准 完成；MR093 2026-09-15 固件复核 完成。用「开始日期」「结束日期」原生date输入和「筛选记录」，闭区间筛选；只D009用于测试此功能。

电价表：T001「园区标准」范围2026-01-01至2026-12-31、日间06:00-18:00单价0.68、尖峰18:00-22:00单价1.20、夜间22:00-06:00业务规定0.38元/kWh。T001详情UI故意显示夜间0.83，属BUG01；其他值不得错。T002「节假日」范围2026-10-01至2026-10-07、全天0.50。各行「详情」dialog名「电价详情」，h2精确T001/T002。仅T002显示「适用范围说明」，打开嵌套同名dialog，文字「仅在2026-10-01至2026-10-07生效」，「关闭说明」留住父弹窗。

审计：9条AU001..AU009，每页3条，默认ID升序；AU003与AU008结果「失败」，其余「成功」；操作文字「读取设备 D001」等非关键装饰不作为预期。筛选「结果」全部/成功/失败和「查询」，筛选后回第1页，失败仅AU003/AU008。

工单种子一条WO-SEED「既有巡检」，设备D001、优先级中、周期7天、执行日期2026-10-01、状态待执行。新增记录localStorage保存，仅练习域可见。列表显示编号/名称/设备/优先级/周期/日期/状态/操作；「新建工单」开启dialog「新建工单」，3步：

1. h2「基本信息」：工单名称必填且trim、最长30字符，设备原生select D001..D012（option显示ID和名称），按钮「下一步」。空名称时显示「请填写工单名称」，停留当前步，不建记录。
2. h2「执行配置」：优先级自定义下拉触发button名「优先级」、listbox/option低/中/高（键盘上下/Enter/Escape可用）；巡检周期数值1..30，执行日期原生date必填，原生「上一步」「下一步」，有明确校验消息。
3. h2「确认提交」：显示所有输入和「提交工单」。提交前未创建记录；只有名称唯一才创建，重复时消息「工单名称已存在」，不关闭、不创建。成功产生唯一运行时WO-<时间戳+序号>，列表可见，状态待执行；不预知编号。生成ID无外部服务。

任一步「取消」；输入有变更则弹出嵌套dialog「放弃编辑确认」，「继续编辑」保留所有输入，「放弃修改」关闭全部且不建记录。未修改直接关闭。上/下一步保持值，不做业务提交。只新建记录的行提供「编辑周期」dialog「编辑工单」，h2编号、工单名称可见，周期1..30，「保存周期」「取消」；和「删除本轮工单」，二次确认dialog「删除工单确认」，显示该编号/名称，「确认删除」只删除当前新建记录，种子不能删除/编辑。

## 交付验收与边界

独立浏览器验证真实交互、数据隔离、菜单/路由、动态/遮挡状态、24例原生导入、只服务静态白名单、窄屏与桌面。两处故意缺陷是用于验证报告真实性，不得“修复”为正确显示。有效例跑不动是Agent能力缺口候选，不应自动认定用例错误。站点正确和测试用例可导入不等于Agent完成测试。
