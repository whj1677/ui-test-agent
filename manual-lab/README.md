# 复杂 UI 人工实测包

这是一套独立的合成业务网站，不是新版本 Agent。网站与用例由 Kimi 按 Codex 事先冻结的 [业务规格](SPEC.md) 编写；Codex负责落盘、独立浏览器核验和交接。无真实业务数据、账号密码或在线资源。

## 开始操作

1. 先在项目根目录终端运行 `node .\manual-lab\serve.mjs` 并保持终端打开，再打开站点 **http://127.0.0.1:4196/**，点「进入演示」熟悉首页。它和 Agent 控制台 http://127.0.0.1:4179/ 是两个服务。本次后台常驻启动被环境策略拒绝，不能假定4196已在运行。
2. 在 Agent 控制台**新建任务**，目标网址填 `http://127.0.0.1:4196/`，导入下面一个 JSON 文件；先不要一次导入所有组。每组、每轮建议独立新任务，旧任务不动。
3. 在 **Agent 自己打开的浏览器**中点「进入演示」，停在「运营总览」。你普通浏览器已登录，不代表 Agent 浏览器也登录了。然后按控制台确认登录/准备流程操作。
4. 先选 LAB-V01～V05，观察能否从首页找菜单、定位同名对象、处理抽屉与叠层；跑顺后再测其余只读项，再测草稿与写入项。没有页面入口 URL 的用例是刻意测自主找入口，不需要你替它导航。
5. 如果还没有配置 Agent 模型连接，在本机控制台设置；**练习站点本身不需要 Key**，也不会外发资料。本包不改变现有模型配置或实验开关。

## 数据、写权限与重跑

- 所有数据仅存在练习站点浏览器的 localStorage。新上下文会回到种子状态；同一任务中的隔离上下文以 Agent 的实现为准，不应假定互相共享新建记录。
- 每例独立，不依赖上一例的工单。写入只针对合成站点，LAB-V13/V17/V18涉及提交，V14～V16涉及表单草稿。按用例分组配置允许的操作；如果现有模式仅只读，写入被阻止不等于本用例有错。
- 重跑写入用例前，在 **Agent所用浏览器**回到总览，点「重置演练数据」并确认；该动作只重置本练习站点的命名空间，不清空 Agent 任务。**不要在探索或执行还在运行时重置。** 或新建独立浏览器上下文，重新进入演示。
- LAB-V18自行创建并只删除其新工单。种子「既有巡检」不允许编辑/删除。不要给真实业务站点授权。
- 遥测是确定性“首次失败、重试成功”，重新打开详情会重新开始，避免误把可恢复读取错误当终止理由。

## 重新启动网站

在项目根目录终端运行，窗口保持打开：

```powershell
node .\manual-lab\serve.mjs
```

或 PowerShell 执行 `.\manual-lab\start.ps1`。默认固定4196；如果端口占用，启动器不会杀旧进程，请先确认已有站点是否正在运行。按Ctrl+C只停止新站点，不停止4179 Agent。

## 完成边界

网站可运行、用例可导入和夹具检查完成，不代表 Agent 已测试通过。这里有自定义下拉、动态创建记录等较难能力；若 Agent 当前不支持，要保留计划、事实、原用例与错误输出，不应把有效用例改成简单版本掩盖缺口。此次不自动启用实验运行时绑定、不切换旧服务构建、不调用真实模型。
