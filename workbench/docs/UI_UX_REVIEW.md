## 3. 六个走查问题的实际结果

1. **进入项目后能否直接找到用例和下一步**：进入项目默认落在用例库，用例表格可见，但被测试概况挤到首屏之下；"下一步"无引导——有待确认内容时只有徽章，没有"去确认"入口；空项目有"暂无用例→上传 Excel"提示，是唯一清楚的下一步。
2. **用例库是否被重复统计、结果列表挤占**：是。同一页依次铺开统计条（全部/已确认/待确认/修订）、测试概况（4 个指标＋6 张逐用例结果卡＋最近运行）、用例表格，结果区约占首屏一半，表格被压到第二屏。
3. **从一条用例能否理解内容/脚本/运行**：内容可读（正文、步骤、逐步预期完整）；但**脚本准备状态、能否运行、缺什么完全看不到**——TC-001 只有"创建演示建例任务"按钮，TC-004～006 连按钮都没有且不解释原因（实为 E2E-01 演示授权只放行 TC-001～003 的 v1 已确认用例），脚本状态要去建例任务列表按编号自行对照。
4. **登录环境和角色在哪里查看**：只在"登录准备"页（4331 @8127e33）。页面本身有明确警示"建例任务尚未绑定此登录环境"，但用例详情、建例任务创建处都看不到登录/环境状态，登录准备与当前任务之间只靠一段说明文字关联。
5. **从失败结果进入后能否直接看到失败步骤/预期实际/回放**：能力都在（断言不符＋预期/实际＋步骤证据回放＋逐步截图），但从测试概况点"查看详情"后落在 39 行索引表顶部，需滚过全表才到结论与媒体；失败结论与回放不在第一屏。
6. **返回列表后项目、筛选、分页、所选对象是否保留**：基本合理。SPA 会话内筛选/分页/勾选保留，执行记录选中行高亮且 run_id 在 URL 中可直达；刷新页面后筛选重置（可接受，本轮不动）。

## 4. 重点问题 A–F 核对结论与分类

- **A. 侧栏与项目 Tab 重复 — 确认，纯前端显示问题。** 侧栏（项目/登录准备/建例任务/执行记录）与项目 Tab（用例库/登录准备/建例任务/执行记录/项目设置）三项完全同目标重复；侧栏反而缺"用例库、项目设置"。见登录准备截图（侧栏与 Tab 同现）。
- **B. 用例库三合一 — 确认，纯前端显示问题。** 统计条＋测试概况＋用例表格同页；空项目也展示全零测试概况。用例表格才是该页主体。
- **C. 内部术语门槛 — 确认，措辞属前端问题；入口限制属合成验证场景。** "建例、候选、正常入口、对照入口、创建演示建例任务、受控演示候选试跑 · 尚未批准"要求测试人员先理解内部管线。其中"演示建例任务仅限 TC-001～003、正常/对照成对试跑"是 E2E-01 合成验证授权，不是通用能力，不能包装成通用 UI 缺陷；但措辞分层（业务语言为主、内部词进说明/折叠）是前端可改的。
- **D. SHA/run_id/Harness 记录默认铺开、缺"下一步" — 确认，纯前端显示问题。** 用例库 eyebrow 是完整 project UUID；用例详情 eyebrow 是完整 case UUID，来源追溯默认展开完整 SHA-256；执行记录索引表含候选哈希、Run ID 两列共 39 行；建例任务详情默认展示 Harness 启动记录。这些信息应折叠但保留可查。
- **E. 登录与用例操作割裂 — 确认，两类原因并存。** 入口与状态展示位置是前端问题；但"登录会话真正绑定建例/执行"后端尚未接通（REQ-0035 与 AUTH_01_USER_GUIDE 均明确现有六用例任务不复用该会话），本轮只把入口、状态和"缺登录"提示前置到需要它的操作旁，不伪装成已接通。
- **F. 结果页索引过重 — 确认，纯前端显示问题。** 失败结论、逐步预期/实际、步骤回放应置顶；索引表应精简（默认只显示必要列、可筛选失败）并下沉。原始录像与步骤回放当前已有文字区分（"非原始连续录像"），调整时保留该区分。

分类汇总：
- 已实现功能的显示/交互问题：A、B、C（措辞层）、D、E（入口与状态前置）、F。
- 后端尚未接通：登录会话与建例/执行的绑定（REQ-0035）；通用被测环境管理；批量操作、测试套件、通用审批。
- 仅影响合成验证场景的特殊入口：E2E-01 演示建例授权（TC-001～003 限定）、正常/对照入口成对试跑、AUTH-01 合成环境为唯一可登录环境。

## 5. 最重要的 4 个问题

1. **用例详情看不到自动化全貌**（走查 3）：内容、脚本准备、运行结果三处信息分散在三张页面，且"不能运行缺什么"无任何说明。
2. **用例库主体被挤占**（B）：测试概况压住用例表格，统计重复。
3. **结果详情结论与媒体不在第一屏**（F）：39 行索引置顶，失败结论要滚一屏多才看到。
4. **导航重复且关键状态不可见**（A＋E＋D）：双套导航并存；登录/环境状态远离用例操作；内部 ID 默认铺开而"下一步"缺失。

## 6. 当前操作路径与建议路径

- 看一条用例能不能跑：
  当前：用例库 → 用例详情（只有内容）→ 记住编号 → 建例任务列表 → 逐行对照编号 → 任务详情找候选与运行。
  建议：用例库 → 用例详情，同页分三区直接看到"内容状态 / 脚本准备 / 最近运行"，不能运行时就地说明缺什么（内容未确认 / 未生成脚本 / 环境未登录）。
- 查失败原因：
  当前：用例库测试概况卡片 → 执行记录（39 行索引顶部）→ 滚动约 1700px → 结论/预期实际/回放。
  建议：测试概况卡片 → 结果详情页第一屏即失败结论（失败步骤＋预期/实际）＋步骤回放；索引退为页面侧栏或独立列表页。
- 准备登录环境：
  当前：发现入口失败或看文档 → 切到"登录准备"Tab → 选环境角色 → 打开专用浏览器 → 回来点检查 → 再自行回到用例/任务。
  建议：在用例详情/建例任务的"运行条件"区直接显示当前环境与登录状态，未登录时给出"去登录"链接，登录完成后回到原操作。

## 8. 只改前端 vs 依赖 AUTH/后端接线

只改前端（本轮建议范围）：
- 导航去重（删侧栏重复项，项目内单套导航）；
- 用例库布局：概况压缩、结果列并入表格、表格为主体；
- 用例详情三区分区、哈希/UUID 折叠、"不能运行"原因文案（原因由已有数据推导，如内容状态、是否有候选）；
- 结果详情重排：结论/媒体置顶、索引折叠；
- 术语分层：业务语言为主，内部词（建例/候选/对照入口）进说明或折叠。

依赖 AUTH/后端接线（本轮不动，只留接口位置）：
- 登录会话与建例/执行的绑定与执行中失效处理（REQ-0035 后续）；
- 用例详情"运行条件"区显示真实登录状态（需任务绑定环境后才有意义）；
- 通用被测环境管理、批量操作、测试套件、通用审批（列为后续项，无后端能力不开发）。

## 9. 建议第一批修改范围（待用户确认后执行）

1. 项目内导航去重：删除侧栏与 Tab 的重复项，保留一套（影响全部项目页面，改动集中在 `web-v2/app.js` 的导航渲染）。
2. 用例库：测试概况压缩为一行概要，用例表格增加"脚本准备、最近结果"两列并上移为主体。
3. 用例详情：加"自动化准备"区（脚本状态＋生成/运行区分＋不能运行原因），UUID/SHA 折入"来源与追溯"折叠区。
4. 结果详情：失败结论与媒体置顶，运行索引默认折叠。
不在第一批：登录状态前置展示（等 AUTH 接线）、术语全量改写、旧 `/` 单页处置（保留入口，另行决定）。
