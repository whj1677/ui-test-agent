### Playwright时钟实现和独立校准

已检查本机锁定的 Playwright 1.62.1 源码：`workerProcessEntry.js` 的 `test.step` `startTime/endTime` 使用 `monotonicTime()`；`coreBundle.js` 的页面创建和Trace帧 `timestamp` 也使用单调时钟。Trace帧同时记录 `frameSwapWallTime` 与JPEG资源。`videoRecorder.ts` 将该帧的 `frameSwapWallTime` 传给编码器；编码器以首个收到帧作基准，以25fps量化后写入WebM PTS。故 `page.time`、Trace帧到达时间与WebM播放PTS不是可互换的“同一个零点”。

新增隔离页面校准：纯本机页面按固定顺序呈现蓝灰、红、绿、紫、青五种大色块，显式等待500ms录制启动并用真实 `test.step` 包围四次变化；页面另有只用于该校准夹具的可见动态色带，为静止画面提供独立的帧身份信息。曾有静止底色夹具运行被严格映射门槛拒绝，诊断发现同一静态画面可对应多个录像时刻；之后仅增强夹具的视觉时标并把Trace/录像缩略图的单帧接受门槛收紧至平均RGB差8，不放宽生产拟合误差门槛。动态视觉夹具的重复真实录制均由 `npm run test:e2e01-clock-calibration` 验证：PTS 0解码像素为黑色空白帧，首个蓝灰页面帧在0.04秒；各次匹配25–27个Trace/JPEG与已编码WebM视觉帧，观测拟合残差46–80ms，含40ms视频帧量化后的精度界87–120ms；四个test.step起点与真实颜色变化的最大观测偏差31–81ms，最近相邻步骤边界半间距不小于166ms。测试显式断言精度界小于最近半步边界。可复核的机器报告及媒体路径在 `workbench/.local/e2e01-video-clock-calibration-*/calibration-summary.json`；收集器日志位于 `workbench/.local/e2e01-delivery-clock*.log`。均留在 `.local`，未提交。

生产映射现在要求同一唯一页面的Trace JPEG与实际解码WebM画面匹配；缩略图平均RGB差不高于8的帧才作为对应证据，使用Trace单调时钟到WebM PTS的固定单位换算，只从实测视觉帧估计零点；记录匹配帧、映射截距、残差和精度。若画面唯一状态不足、残差过大，或精度界达到相邻实际步骤起点间距的一半，则返回不可用；不平均分段、不扩大容差来恢复绿色状态。派生交付输出使用 `captioned-v2.webm`，不会覆盖旧 `captioned.webm`。
