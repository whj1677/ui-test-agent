## 1. 版本选择修复

修前实际复现：先查看项目 A 用例 v1，再打开当前版本为 v2 的项目 B 用例且 URL 不带 `version`，页面沿用全局 v1，真实 Chromium 在等待“设备监控 · v2”时超时。

修后规则：

- URL 不带 `version`：精确读取当前用例自己的 `current_version`。
- URL 带 `version`：只接受正整数，并在当前用例 `versions` 中精确查找。
- 参数非法、版本不存在或当前版本正文缺失：显示“无法显示用例版本”，不回退到最后版本。
- 项目/用例切换不使用其他对象的 `state.caseVersion`；刷新、直接链接和浏览器后退使用相同 URL 规则。
- 只有 `version === current_version` 显示“编辑当前版本”；历史版本只读。

修后真实浏览器覆盖 A v1 → B 默认 v2、刷新、`version=9999`、`version=bad`、后退以及编辑入口，`npm run test:ui-d2a-browser` 1/1 通过，执行接口请求 0。

2. 先做 `npm ci --ignore-scripts --dry-run`，再执行 `npm ci --ignore-scripts`。没有执行依赖安装脚本、DSH 初始化、插件配置、模型或业务用例。

依赖版本和 `package-lock.json` 未修改。`npm audit` 报告 5 个中等级间接依赖问题；为保持 DSH/Playwright 锁定组合，本批未运行强制升级修复。

- `CaseLibraryManager/Store`：项目、用例版本、内容哈希、导入和正式导出。
- `POST /api/build/tasks/from-project-case` 与 `BuildTaskManager.submitProjectCase`：按项目 ID、内部用例 ID、版本、内容哈希、环境 ID 和 request ID 冻结任务。
- `assembleProjectCaseInput`：生成 `case-snapshot.json`、`task.md`、Agent 指令和步骤标记；反例材料留在控制器侧。
- 现有 attempt 生命周期、30 次工具/600 秒边界、取消和失败收尾。

### 需要的最小修改

1. 在新墨白用例详情增加“创建建例任务（尚未启动）”，调用现有 `from-project-case` API并显示冻结输入、INPUT_ONLY 状态和来源关联；不能直接加入启动按钮。
2. 为该真实项目增加一个精确环境定义：只允许已确认入口、用例内容绑定和正常验证配置。当前项目用例环境固定为 `synthetic-probe-normal-v1`，不匹配真实站点。
3. 若环境需要登录，增加任务私有、Git 忽略的本机会话引用。优先由用户在任务拥有的浏览器上下文中登录；当前代码没有把真实业务 storageState 绑定到环境的通用能力，不能继承完整宿主 Cookie 或要求明文凭据。
4. 为精确的项目/用例/版本/哈希登记单次授权；继续保持历史 INPUT_ONLY，不设置全局执行开关。
5. 将生成后的验证记录和媒体按现有 `project_id/case_id/case_version/task_id/candidate_sha256` 关联回新页面。展示层可复用旧工作台媒体 API，不需要重做播放器。
6. 若需要受控反例，必须由业务方在生成前确认其来源与可外发范围；没有已冻结反例时先只做正常候选试跑，不临时从页面或脚本结果反推验收答案。
