# M3-A Excel 首版格式

仓库中没有用户提供的真实 Excel 模板。本阶段只承诺支持 [M3A_CASE_IMPORT_TEMPLATE_V1.xlsx](../examples/M3A_CASE_IMPORT_TEMPLATE_V1.xlsx) 所示的一行一条用例格式，不宣称自动识别任意表格。

## 支持的结构

- 用户先选择工作表，再明确映射：用例编号、标题、模块、前置条件、测试数据、步骤、逐步预期、内容状态。
- `用例编号`、`标题`、`步骤`为必需映射；编号应存为文本，前导零按原值保留。
- `步骤`和`逐步预期`各占一个单元格，以换行拆分，并严格按单元格内原始行号一一对应；步骤顺序另存为 `order`，不靠改写原文推导。
- 导入器不自动删除看似序号的行首。`220.5 kW`、`3.65 V`、`127.0.0.1`、版本号、中文和其他原动作/预期文本均按原值保留。
- 工作表中的物理空行可以存在；导入器跳过空行，但来源位置继续使用原工作表行号。表头之间也可以存在空白列，映射按真实列位置读取，不会用“非空列数”截断后续字段。
- 中文、多行前置条件、多行测试数据均按原文保存；导入器不概括、不补写。
- 某一位置有动作但缺预期时，该动作保留并标为“内容待确认”；有预期但缺动作时无法确定归属，该用例不可导入。两边同一位置都为空则跳过该位置。任何这类歧义记录都不会自动标为“已确认”。
- 内容确认仅表示用例文本已确认，不代表脚本批准或测试通过。

## 明确不支持

- 跨多行表示一条用例、合并单元格推断步骤归属、仅凭标题猜测字段。
- `.xls`、`.xlsm`、宏、公式求值和外部链接取值。映射字段含公式时按具体行和字段报错。
- 把数字单元格中的 `1` 猜回 `001`。源文件若要保留前导零，必须把编号存为文本。
- 重复表头、缺少映射表头，或无法可靠确定字段列位置的结构；此类结构会明确报错，不会静默截断。

上传原文件只保存在 Git 忽略的本地目录。公开导出的 JSON 用例包不包含绝对路径、脚本、批准状态、执行结果、媒体、Cookie 或凭据。

此前版本导入的数据可能受三类旧行为影响：看似数字序号的动作/预期前缀被删除、物理空行后的用例遗漏、步骤与预期各自去空行后错位。系统不会批量猜测或改写已有项目；需要更正时，应从本地保存的原文件重新生成预览并由用户明确确认。原文件缺失时，已丢失的文本或对应关系无法可靠重建。
