## 实现边界

- 存储：`workbench/.local/case-library` 下的项目单文件、上传登记和预览记录；串行写入、同目录临时文件替换、有限 Windows 占用重试。
- 并发：预览冻结项目 revision；确认前 revision 变化会拒绝并要求重新预览；同一 preview 重复确认幂等读回。
- Excel：锁定 `exceljs 4.4.0`（MIT），`uuid 11.1.1` override 消除已知审计项；不执行公式、宏或外部链接。`npm audit --omit=dev` 为 0 个已知漏洞。
- 原生包：保留根来源、目标项目 lineage 和当前来源版本，在目标项目创建新内部 ID；不携带自动化资产或本机路径。
- Web：所有文本使用 DOM `textContent`，文件读取按登记 ID，状态变更仅接受本机同源请求；没有开放 `.local` 静态目录或任意路径参数。
- Excel 适配边界详见 [M3-A Excel 首版格式](M3A_EXCEL_FORMAT_V1.md)。

## 真实 Web 十步结果

1. 项目A从真实模板的“项目A示例”工作表预览并导入 3 条：2 条新增、1 条缺少预期的待澄清记录。
2. `001` 前导零、中文、多行前置/测试数据、3 个步骤及逐步预期均由后端记录核对保留。
3. 在项目A勾选 2 条并通过浏览器下载实际 JSON 包；包内为 2 条且多步骤未丢失。
4. 项目B先从同一 Excel 的“项目B示例”导入 1 条，再从下载包导入 2 条，共 3 条、两种来源。
5. 项目B的内容、逐步预期和根来源均与包/Excel机读记录一致。
6. 再次上传同一包，预览显示重复 2 条，确认后项目B仍为 3 条。
7. 项目B中的 `001` 修改为 v2；项目A同源用例仍为原标题和 v1。
8. 独立临时冲突包使用相同根来源但不同标题，预览为冲突；默认确认跳过且未覆盖。
9. 项目B全部导出并导入空项目C，3 条支持字段和来源往返一致，内部 ID 独立。
10. 服务关闭后以同一数据目录重新建立实例，三个项目和用例记录仍可读取。
