# M2-C 最小候选建例入口验收报告

日期：2026-09-21

基线：`13f2c411b56962b44550fe8fc9cc4acd4866a187`

分支：`codex/test-workbench-m2c-build-ui`

## 结论

**部分实现，真实集成受阻。** 最小 Web 入口、Harness 适配、持久化状态、阶段预算、候选双向验证编排、显式一次修订、取消与文件边界已经实现并通过工程验证。真实 Web 也确实提交并启动了一个新任务，但拥有该任务的进程在 Harness 生成阶段、候选落盘之前消失。工作台重启后将任务和活动尝试同时标为 `INTERRUPTED`，没有自动重放，也没有把剩余一次额度改作第二次初始建例。

因此本轮没有取得候选文件、正常 Playwright 报告或错误输出反例报告，不能进入“技术验证通过，等待人工核对”，更不能登记为批准资产。该结果不是 M2-A/M2-B 旧候选的复用。

## 实现范围

- 固定模板 `synthetic-probe-v1`，只允许工作台管理的本机 `/probe` 合成入口；提交时冻结任务版本、预期与 SHA-256。
- 独立 `build task` 存储和跨任务阶段预算；最多一个活动建例，阶段最多 2 次 Harness 启动，每次最多 30 次工具调用和 600 秒。
- 复用 `harness-probe` 的受控进程、事件、合成站点和候选执行原语，没有搬入一次性探针主程序，也没有修改 Harness 核心。
- 任务、候选生成、技术验证和人工核对状态独立；Harness final 不能覆盖候选文件与结构化报告事实。
- 同一候选计划执行正常页面和未提供给 Harness 的 `PROBE-41` 反例；通用报告解析器不按样本常量猜测断言结果。
- 候选失败时只开放一次显式修订；旧候选、错误和版本保留。刷新或重启不会恢复模型调用。
- 候选、工具日志、页面快照和报告分类登记；工具文件默认不向 Web 公开，读取需同时满足任务登记、路径边界、大小和哈希。

本阶段延续用户接受的“独立任务目录＋最小资料暴露”策略，但没有操作系统级文件或网络强制隔离；路径与环境约束不被描述为沙箱。

| 入口 | 实际结果 | 覆盖边界 |
|---|---:|---|
| `npm test`（`workbench`） | 33/33 通过 | 模板、预算持久化、重复启动、取消、重启中断、通用报告、显式修订、API 来源/结构、文件边界及 M1 回归 |

| `npm test`（`harness-probe`） | 19/19 通过 | Harness 终态、工具证据、取消、超时、脱敏、隔离审计和进程控制回归 |

真实集成后的集中修复补齐了“服务重启时活动 attempt 也必须落为 `INTERRUPTED`”的事实一致性。随后工程复验真实复现了一次 Windows `EPERM`：build task 临时文件替换目标 JSON 时失败。build 存储因此增加只针对 `EPERM`/`EACCES`/`EBUSY` 的有限重试，后台 completion 也显式吸收未观察拒绝以避免进程被未处理 Promise 直接终止；修复后 `workbench` 33 项集合连续运行 10 轮均退出 0。没有为验证该修复而重启模型任务。
