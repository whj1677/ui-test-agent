# 台账合成练习：人工核对参考

> 状态：合成练习用的人工核对参考。它不是已批准用例，不代表已执行结果或真实业务验收；不要上传给生成模型，也不要据此生成脚本或执行计划。

## 范围与共同前提

依据 `workbench/qa/20260926-req0038-completion/CASES.md` 的 B-R1、B-R2、B-R3 业务判据及同目录 `PROTOCOL.md` 的接口契约。设备页面 `workbench/qa/20260926-req0038-completion/fixture/ledger.html` 仅供核对页面技术名称和可访问 label；步骤按页面可见名称操作，不把 DOM id 当业务规则。

目标是公开合成设备台账。每个场景都使用一个此前未用过的全新 `runId` 和独立 namespace；不得复用或假定初始化会重置已有空间。公共初始台账只有 `DEV-001 / 循环泵一号 / 东站 / 80 kW`，它必须保持不变。每个场景结束后，只清理本场景的 namespace，再独立读取公共基线，确认仍只有原始 `DEV-001`。下列三种操作各在 UI 和 BACKEND 各列一例；六例彼此使用不同的新 `runId`。

viewer 对合法新增的拒绝是该场景的预期结果：核对拒绝响应、后置数据未变，即符合此人工判据。它不是故障注入或产品故障判据。

## UI 人工参考

### UI-1：正常新增 DEV-007

1. 在“运行命名空间”填入本例新 `runId`，保留“公开合成角色”为 `editor`，点击“初始化本次台账”。预期看到全新运行提示；初始列表为 DEV-001 一条、总数 1。
2. 按可访问 label 填写“设备编号”`DEV-007`、“设备名称”`冷却泵二号`、“所属站点”`西站`、“额定功率（kW）”`110`，点击“提交新增”。预期显示新增成功反馈。
3. 核对页面重新读取后的列表：DEV-007 恰好一条，名称、站点、功率分别为冷却泵二号、西站、110；DEV-001 四个字段与提交前一致；总数为 2。
4. 点击“清理本次运行”。预期显示当前运行已清理，当前显示的是独立读取的公共基线，只有 DEV-001 原始四字段，总数 1；不再是活动运行结果。

### UI-2：重复编号 DEV-001 不得覆盖

1. 使用另一全新 `runId` 初始化，角色选 `editor`。预期初始列表只有原始 DEV-001、总数 1。
2. 填写 `DEV-001 / 不得覆盖的设备 / 西站 / 110 kW` 并提交。预期页面给出有意义的重复说明及拒绝反馈；本条 UI 参考不要求页面显示 HTTP 状态或错误码。
3. 独立重新读取列表。预期 DEV-001 恰好一条，四字段均与前置记录一致，总数仍为 1；没有新增或覆盖。
4. 点击“清理本次运行”。预期显示当前运行已清理，列表显示独立读取的公共基线 DEV-001 原始四字段，总数 1。

### UI-3：viewer 提交 DEV-008 应被拒绝

1. 使用第三个全新 `runId`，将“公开合成角色”选为 `viewer` 后初始化。预期列表为公共 DEV-001 一条。提交按钮仍可观察和操作；按钮是否隐藏不作为拒绝判据。
2. 填写 `DEV-008 / 观察泵三号 / 西站 / 110 kW` 并提交。预期页面显示服务拒绝反馈；本条 UI 参考不要求页面显示 HTTP 状态或错误码。
3. 独立重新读取列表。预期 DEV-008 不存在，DEV-001 与前置完全一致，总数仍为 1。
4. 点击“清理本次运行”。预期显示当前运行已清理，列表显示独立读取的公共基线 DEV-001 原始四字段，总数 1。

UI 各例清理后的页面会单独读取公共基线并展示。操作者也可打开 `http://127.0.0.1:4401/__control/baseline` 补充核对，额外人工检查与 UI 脚本结果分开记录。

## BACKEND 人工参考

以下使用 `PROTOCOL.md` 中公开合成服务的 HTTP/JSON 契约。每例均须换用全新 `runId`；`{runId}` 表示本例实际值。独立读取指另发 GET 查询，不以 POST 响应体替代持久化核对。

### BACKEND-1：正常新增 DEV-007

1. `POST /__control/namespaces` 初始化本例新 namespace；预期 HTTP 201、`created:true`。`GET /api/v1/namespaces/{runId}/devices` 保存前置列表：仅 DEV-001，完整字段为循环泵一号、东站、80 kW。
2. 以 `x-synthetic-role: editor` 向 `/api/v1/namespaces/{runId}/devices` 提交 `{ "code":"DEV-007", "name":"冷却泵二号", "site":"西站", "ratedPowerKw":110 }`。预期 HTTP 201、`created:true`。
3. 独立 GET 整个台账并查询 DEV-007。预期该设备恰好一条且四字段准确；DEV-001 与前置完整对象一致；总数 2。
4. `DELETE /__control/namespaces/{runId}` 清理本例空间；预期 HTTP 200、`deleted:true`。随后 GET 本例 `/api/v1/namespaces/{runId}/devices` 应为 404 `NAMESPACE_NOT_FOUND`；GET `/__control/baseline` 应仅有原始 DEV-001 完整四字段、总数 1。

### BACKEND-2：重复编号 DEV-001 不得覆盖

1. 初始化另一个全新 namespace，预期 HTTP 201、`created:true`；GET 整个台账并保存 DEV-001 完整对象及总数 1。
2. 以 `editor` 向本例 `/devices` 提交 `{ "code":"DEV-001", "name":"不得覆盖的设备", "site":"西站", "ratedPowerKw":110 }`。预期 HTTP 409、`created:false`、错误码 `DUPLICATE_CODE`，并有非空重复说明。
3. 独立 GET 整个台账和 DEV-001。预期 DEV-001 恰好一条且四字段与前置一致，总数仍为 1；未新增、未覆盖。
4. DELETE 本例 namespace，预期 200、`deleted:true`；再 GET 本例业务路径应为 404 `NAMESPACE_NOT_FOUND`，GET 公共基线应为原始 DEV-001 完整四字段、总数 1。

### BACKEND-3：viewer 提交 DEV-008 应被拒绝

1. 初始化第三个全新 namespace，预期 HTTP 201、`created:true`；GET 整个台账，保存只有 DEV-001 的前置状态。
2. 以 `x-synthetic-role: viewer` 向本例 `/devices` 提交 `{ "code":"DEV-008", "name":"观察泵三号", "site":"西站", "ratedPowerKw":110 }`。这些字段是协议提供的合法合成数据。预期 HTTP 403、`created:false`、错误码 `FORBIDDEN`，并有非空拒绝说明。
3. 独立 GET DEV-008 和整个台账。预期 DEV-008 不存在，整个台账与前置一致；未发生写入。此项按拒绝判据核对，不按故障注入或产品故障处理。
4. DELETE 本例 namespace，预期 200、`deleted:true`；再 GET 本例业务路径应为 404 `NAMESPACE_NOT_FOUND`，GET 公共基线应为原始 DEV-001 完整四字段、总数 1。
