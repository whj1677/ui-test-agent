## 你自己跑一遍

先进入“项目配置 → 项目测试环境”。本练习项目已固定 UI 为设备台账 `/ledger/`，HTTP 为同一 4401 根地址；生成、示范和运行沿用该绑定，操作弹窗不再选择环境。需要换目标时在此页显式创建或选择并保存，旧脚本和计划仍按原环境身份核验。

1. **阅读资料。** 打开项目“资料与用例设计”，对照三份本地文件。本次状态为评审稿，需要你核对。如果你要把资料状态登记为已确认，在“添加资料”逐份选择原角色、同一文件、版本 v1、“明确替代原资料”中对应原快照，以及“文档状态：已确认”，保存新快照；旧评审稿保持。后续只选最新采用快照，不同时采用同一文件的两份版本。也可先用评审稿分析，保留其待核对问题，不能跳过人工决定。
2. **生成候选。** 勾选采用的 PRD、MRD、协议，首次可以选“本期全部”，按页面提示确认本次模型处理范围，再点“分析资料并生成候选”。只有你点这一步才开始业务模型请求；普通“全部”会串行生成前后端，页面标明最多两次请求。增强检查可按需要另选，其调用范围以页面提示为准。本次资料没有图片，不需要图片授权。
3. **核对并确认用例。** 分别看前端/后端候选，对照人工参考核对三个场景、原数据、来源和每步预期。特别检查独立重新读回、DEV-001 不变和精确清理。保留待澄清项，修改或记录决定后再确认所选用例。建议第一遍各选一条正常新增，跑顺后再做拒绝场景。候选数量不作为质量判据。
4. **前端路径。** 在用例库打开已确认的前端用例 → “自动化脚本”或“重新生成脚本”，核对自动带入的项目环境“设备台账 · 本次合成练习 UI”，核对页面给出的本次资源范围后明确生成。逐步审阅脚本与实际自测证据；若需要精确候选的技术试跑授权，由你在当前候选上明确操作。随后“运行此用例”或批次复跑，填写本轮软件版本标签 `synthetic-ledger-v1`。这个标签是人工练习标签，不是部署证明。
5. **后端路径。** “协议绑定”选择已确认后端用例及本次协议，逐步填写方法/路径、输入、独立业务观察与清理依据，勾选对应协议原文并确认本条技术映射。进入该用例的 HTTP/JSON 计划，核对自动带入的项目环境“设备台账 · 本次合成 namespace”，再明确生成。审阅请求、断言、初始化与清理，确认计划后才执行；上传协议本身不会生成完整绑定，也不会执行。
6. **看报告。** 在“执行结果”“测试批次”“报告”查看本轮结果和所选运行的证据，再导出离线 HTML。既有脚本复跑不调用模型；重新生成和基于问题修订需要新的显式模型操作。错误、失败或未执行保持原状态，不覆盖原记录。

若使用“指定功能”，可粘贴：
