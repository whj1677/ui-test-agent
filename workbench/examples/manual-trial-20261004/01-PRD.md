# 设备台账登记：本地练习需求 v1

这是公开合成练习资料，无真实客户数据。沿用既有 B 台账 B-R1/B-R2/B-R3 的冻结业务规则，仅用于手动体验测试 Agent。资料由 Codex 整理，尚待操作者核对；不代表真实业务批准。

## 项目与范围

项目名：手动体验 · 设备台账 · 20261004。
业务模块：设备台账登记。相同业务分别设计前端 UI 用例和后端 HTTP/JSON 用例，各自核对结果。
本轮只覆盖正常新增、重复编号拒绝、viewer 只读角色拒绝。每一条用例使用独立、全新的运行命名空间。初始化和清理属于测试准备，不能代替业务步骤。
不包含真实登录、修改/删除设备、复杂查询、分页、金额、故障注入、超时和取消验收。

## R0 固定数据与隔离

全新命名空间的初始台账只有一条记录：编号 DEV-001，名称 循环泵一号，站点 东站，额定功率 80 kW。
公共初始记录只读，不能覆盖。每条用例的新增数据只属于自身命名空间，不得使用另一条用例的产物作前置条件。
公开合成角色 editor 可新增，viewer 只读。角色选择仅模拟权限行为，不是真实账号认证。

## R1 正常新增

editor 提交一个尚不存在的编号 DEV-007，名称 冷却泵二号，站点 西站，额定功率 110 kW。
系统接受创建，显示有意义的成功反馈。随后独立重新读取台账：DEV-007 恰好一条，四个业务字段与输入一致；DEV-001 四字段与提交前一致；总数由 1 变为 2。
不能只根据提示、HTTP 成功码或提交响应判定业务成功；独立读回是必要的业务观察。

## R2 重复编号拒绝

editor 在全新命名空间提交 DEV-001，名称 不得覆盖的设备，站点 西站，额定功率 110 kW。
系统拒绝创建，显示有意义的重复编号说明，不要求消息逐字一致。随后独立读取：DEV-001 恰好一条，仍为 循环泵一号 / 东站 / 80 kW；整个台账与提交前一致，总数仍为 1。
拒绝重复并保持数据不变，是本场景的正确结果。不得把它改写成创建成功。

## R3 viewer 拒绝新增

viewer 在全新命名空间提交合法的新设备：DEV-008，名称 观察泵三号，站点 西站，额定功率 110 kW。
系统拒绝创建并显示有意义的权限拒绝说明。独立读取 DEV-008 为空；整个台账和 DEV-001 四字段与提交前一致，总数仍为 1。
页面保留提交入口供观察服务端拒绝；不能把按钮隐藏当作通过条件。

## 前端页面契约

被测页面为 http://127.0.0.1:4401/ledger/，与正式测试工作台 http://127.0.0.1:4322/workspace/ 分开。
页面依次提供“运行命名空间”“公开合成角色”“初始化本次台账”，以及“设备编号”“设备名称”“所属站点”“额定功率（kW）”和“提交新增”。初始化前不能提交。
初始化后可看到完整初始台账；每次提交完成页面独立重新读取台账，反馈与台账分开显示。“重新读取台账”用于再次读回，不能靠页面缓存或自行补行取代业务结果。
“清理本次运行”只清理当前运行命名空间的新增记录、审计和故障状态。公共初始记录始终保留。
UI 用例只用可见页面操作和列表观察；HTTP 状态与错误码由后端用例依据协议核对，不能要求页面显示未约定的协议细节。
