# 储能站巡检工单：从这里开始

环境已经启动。你自己新建项目、导入材料，再生成和运行脚本。

## 1. 新建项目，配置环境

打开 [正式测试工作台](http://127.0.0.1:4322/workspace/)，新建项目，例如“我的巡检工单测试”。进入项目的环境设置，填写：

| 配置项 | 填写内容 |
|---|---|
| 环境名称 | 储能站巡检工单 |
| 本项目测试什么 | 同时勾选“前端页面”和“后端接口” |
| 前端 Base URL | http://127.0.0.1:4460/inspection/ |
| 访问前端系统需要登录吗 | 无需登录 |
| 后端 Base URL | http://127.0.0.1:4460 |
| 接口环境类型 | **练习台账 · 独立命名空间** |
| 页面允许路径 | `/`，保持默认即可 |
| 本机操作者 | 填你的名字或测试员 |
| 非生产环境授权 | 确认本机合成练习范围后勾选 |

点击“保存并继续 →”。本环境有新增和修改操作，选择上表的独立命名空间类型才能执行。

这是公开合成练习，无真实账号或密码。页面中的 editor / viewer 用来练习权限拒绝，由每条用例明确选择。

## 2. 导入两份用例，再导入协议

在项目的“导入用例”入口，分别导入：

1. `01-前端用例.json`：6 条前端用例。
2. `02-后端用例.json`：6 条后端用例。

每次查看预览后确认导入。导入后应共有 12 条，编号 UI-WO-01～06、API-WO-01～06。这是工作台支持的原生 JSON 格式，已按练习规则冻结为可生成状态；不表示脚本已经执行。

回到“测试工作台”，切到“后端测试”，上传 `03-通讯协议.md`。预期 6 条后端用例均显示“可生成”。协议已经包含请求方法、路径、参数、响应、初始化与清理约束。

`04-需求说明.md` 和 `05-用例说明.md` 用于阅读核对；已有用例导入流程无需再生成一遍用例。

## 3. 由你开始生成和运行

前端：切到“前端测试” → “生成前端脚本（6）”，在当前页看进度及每条结果。

后端：切到“后端测试” → 确认 6 条可生成 → “生成后端脚本”。

生成结束后核对每条结果，按页面提示处理需要核对的脚本或计划，再点击“选择用例并运行”，勾选已就绪用例运行。软件版本可填写 `inspection-v1`。结果在“测试结果”中查看；失败记录保留供检查。

如要体验“人工示范”，在前端用例的“人工示范（可选）”入口自己操作页面、记录关键步骤；不是这次生成的必填项。

## 这套用例测什么

| 编号尾号 | 场景 | 预期结果 |
|---|---|---|
| 01 | editor 新增 WO-2001 | 成功；总数 4；原有三条不变 |
| 02 | 新增重复编号 WO-1001 | 拒绝；不覆盖原记录 |
| 03 | viewer 尝试新增 | 拒绝；列表不变 |
| 04 | 东站 + 待处理组合查询 | 仅返回 WO-1001 |
| 05 | 完成待处理 WO-1001 | 状态变为 DONE；其他字段与记录不变 |
| 06 | 再次完成已完成 WO-1003 | 拒绝；列表不变 |

每种场景都有前端和后端用例。每条执行使用独立运行编号，开始时初始化三条固定记录，结束后清理自己的数据。HTTP 403 / 409 是对应拒绝用例的正常预期，应据此判断用例结果。
