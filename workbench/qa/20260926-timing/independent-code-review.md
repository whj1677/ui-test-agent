# 2026-09-26 时间保真链路独立代码审查

范围：只读核对冻结用例、`timing-obligations`、`timing-observer`、`timing-evidence`、候选包与提交门禁、自测/独立验证/显式试跑、步骤观察和执行详情 UI。没有修改源码、运行模型、启动服务或重新执行正式工作台。主管报告的 102 项工程清单通过及 4322 服务版本属于主管执行证据，本次审查没有独立复跑。

## 结论

对当前 CASE-02 的两处原始“约 400-600ms”，静态链路没有发现已知的 300-2000ms 放宽可再次作为 `ready` 通过的路径：提取器把两个步骤绑定到各自带引号的加载提示和原边界；候选包拒绝候选自有时钟；观察器在页内测量唯一提示的一轮不可见→可见→不可见；校验器要求原边界、步骤、运行身份、候选 SHA、唯一完整周期和零附加容差；自测、正式独立验证及显式试跑均把时间失败并入最终结果。这个结论限于上述有限语法和 DOM 可见时长，不等于整条自然语言预期或产品验收通过。

## 发现

1. **UI 会把未获信任的时间值称为“实测”**（展示准确性，建议修复）。`timing-evidence.mjs:7-20` 在身份不符、重复记录或周期不合法时判 `FAILED`，但 `:21-23` 仍保留首条记录的数值；`web-v2/execution-media.js:18-23` 只判断数值有限，就显示“实测 X ms”和“时间要求未满足”。可构造一条 500ms、但 `run_id`/SHA 错误的记录：运行判失败是正确的，详情却把未通过来源校验的 500ms 当作可信实测，并把证据问题说成超时问题。应区分“测得超出原范围”和“证据缺失/归属无效”；后者不能称为可信实测。`candidate-trials.mjs:256` 的 `failure_step` 仅从 Playwright 归因错误取值，若 Playwright 报告全绿而独立时间证据失败，概要还可能显示“失败步骤：无”，虽然步骤卡会由 `executionSteps` 标红。

2. **时间义务只证明提示可见时长，不证明结果与提示消失同步**（已知语义边界，保留人工核对）。原步骤 1 要求 400-600ms 后“提示消失且列表刷新”，步骤 4 要求约 400-600ms 后显示详情字段（`qa/20260925-release/fixture/cases.json:36,48`）。`timing-observer.mjs:25-55` 只记录提示元素的可见跃迁。如果提示在 500ms 消失，但列表或详情到 2s 才刷新/显示，独立时间义务仍可通过，候选的最终状态断言也可能稍后通过。现有 `development-fidelity.mjs` 明示其他子句需人工复核，因此不得把 `timing_validation.complete` 描述为整句时间关系已证明。

3. **受支持形态有意有限**（非本轮扩展要求）。提取器只识别单一数值范围、同一子句之前唯一带引号的加载提示（`timing-obligations.mjs:25-58`）；它发现但不能唯一解析的数字单位/范围会进入 `NEEDS_REVIEW`，`verify-candidate.mjs:58` 阻止运行时将其误判通过。但“半秒”等没有数字单位的时间语义可能根本不被提取，不能声称所有未支持时间句都由程序阻断；它们仍属于人工语义核对。跨句指代、多个提示或多个时间范围也不由此程序证明。观察器还要求开始时同名 `[role=status]` / `[aria-live]` 元素恰好一个且隐藏（`timing-observer.mjs:7-23`）；点击后才动态插入节点的网站会失败，需要按该网站另定受支持观测方式，不能把这种失败解释为业务时长超界。当前冻结合成页面预置两个隐藏的状态元素（`qa/20260925-release/fixture/index.html:68,93`），符合此入口条件。

## 核对到的门禁

- `development-session.mjs:58-64,96-118` 在写草稿、打包自测和 `ready` 提交处检查候选自有时钟、同哈希自测及完整时间证据；原候选的 `Date.now` 计时会被拒。
- `step-observer.mjs:53-88` 在目标 `CASE_STEP` 的候选回调之前启动可信观察，结束时保存 `timing_observations`；`verify-candidate.mjs:120-139` 从观察文件做独立校验，并把失败并入 `success`。
- `development-evidence.mjs:8-15` 和 `candidate-trials.mjs:174-187` 将时间结果并入运行 `complete_pass` / `test_status`；`execution-media.js:16-24` 把时间结论附在相应步骤实际结果中。
