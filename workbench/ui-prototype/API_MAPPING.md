# UI-D1 现有能力与正式接入映射

| 原型区域 | 当前工程能力 | 正式接入判断 |
| --- | --- | --- |
| 项目、用例、版本 | 已有项目/用例持久化、Excel与JSON包、版本快照 | 可接入；正式页面需要按六屏拆分，不能沿用演示 `sessionStorage` |
| 导入预览 | 已有上传、表头映射、预览确认、冲突重检和幂等 | 可接入；演示夹具按钮需替换为真实受控上传入口 |
| 单条建例任务 | 已有项目用例快照和 build task 双向关联 | 限定场景可接；创建任务不应自动启动模型 |
| Harness生成 | 已有受控调用、生命周期、取消、预算与文件收集 | 仅限已授权环境；原型没有接线，也不能据此显示为通用能力 |
| 候选技术验证 | 已有统一Playwright执行、正常/反例记录与媒体登记 | 限定合成场景可接；技术通过仍需人工核对 |
| 已首审脚本运行 | 已有登记资产、版本适用关系、run/stop/report | 可接登记资产；新用例版本不得自动继承旧资产 |
| 截图、录像、Trace | 已有登记ID、路径/哈希检查和Range响应 | 可接；Trace继续采用受控下载和本地查看，不嵌入外部服务 |
| 批量执行 | 尚未实现 | 明确显示未实现，不提供可点击假入口 |
| 通用Web审批 | 尚未实现 | 不增加批准按钮；原型只展示人工状态 |
| 通用环境管理 | 尚未实现 | 不开放任意URL或凭据配置 |
| 多人权限 | 尚未实现 | 不在D1原型中伪装可用 |

正式接入时必须保留后端事实源、文件登记ID和安全边界；不得把原型数据结构直接当成生产存储方案。
