# UI-D1 页面结构与交互说明

## 设计取向

原型采用桌面测试运营工作台布局：项目为第一入口，项目内固定导航为“用例库、建例任务、执行记录、项目设置”。信息密度偏高，但把业务状态和技术细节分层：默认展示测试人员需要判断的中文结果，哈希、代码、模型配置、原始 JSON 和日志收进可展开的技术详情。

原型不使用外部字体、分析脚本或前端框架。视觉规范使用系统字体、稳定表格、明确焦点、克制动效并支持 `prefers-reduced-motion`。

## 页面结构

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 项目列表 | 项目、用例数、待处理量、最近活动 | 创建项目、进入项目 |
| 用例库 | 紧凑列表、检索、内容/自动化/最近运行三类状态 | 多次导入、查看用例 |
| 导入向导 | 来源、映射、预览、确认 | Excel/平台包切换、冲突处理 |
| 用例详情 | 冻结内容、动作与预期、版本、建例任务、脚本版本 | 查看任务、运行和待处理问题 |
| 建例任务 | 任务、生成、技术验证、人工核对四个独立状态 | 回到来源用例 |
| 执行记录 | 进程、报告、测试、证据和整体状态 | 打开运行详情 |
| 结果详情 | 中文步骤、预期/实际、截图、录像、Trace说明 | 预览媒体、展开技术详情 |

## 状态与操作

| 状态维度 | 示例 | 允许的主要操作 |
| --- | --- | --- |
| 内容状态 | 待确认、已确认、验收范围待确认 | 查看或维护用例，不等同脚本批准 |
| 自动化状态 | 未建例、生成中、待人工核对、候选验证失败 | 查看任务；原型不提供批准动作 |
| 执行事实 | 进程已结束、运行中断 | 查看原始过程事实 |
| 测试事实 | 通过、断言不符、未完成 | 查看步骤与错误，不自动归因产品缺陷 |
| 证据事实 | 证据齐全、不完整、尚无证据 | 查看登记媒体或缺失原因 |
| 整体结论 | 整体通过、整体未通过、尚未结算 | 仅由各事实综合显示，不覆盖原始结果 |

## 现有 API 接入矩阵

| 原型区域 | 当前工作台能力 | 接入判断 |
| --- | --- | --- |
| 项目、用例、版本 | 已有项目与用例 CRUD、版本快照 | 可直接接入，正式改造时需拆分现有长页面 |
| Excel / JSON 包导入 | 已有上传、预览、确认、导出 | 可直接接入，保留预览重检和幂等语义 |
| 单条用例建例 | 已有 build task 和项目用例关联 | 仅限定登记场景，不能展示为任意用例可运行 |
| 候选与人工核对 | 已有候选、技术验证和人工状态字段 | 状态可接入；尚无通用 Web 审批流程 |
| 已首审脚本运行 | 已有资产、run、stop、report | 仅登记资产/允许入口可运行 |
| 截图、录像、Trace | 已有登记 ID、路径/哈希边界与 Range | 可接入；Trace 保持本地查看说明 |
| 批量执行 | 尚未实现 | 原型禁用并标注“规划中” |
| 环境管理 | 尚未实现通用管理 | 不提供任意 URL 或环境编辑 |
| 多人权限 | 尚未实现 | 不在首版原型中伪装可用 |

## 演示边界

演示进度、截图和录像均不是真实执行证据。录像只证明结果区的原生播放交互，没有步骤级时间戳，因此没有设计“点击步骤精准跳转录像”的虚假能力。原型待用户核对后才可决定是否分批迁移到正式 UI。
