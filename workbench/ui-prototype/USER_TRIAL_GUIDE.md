# UI-D1 用户亲自体验指南

## 1. 案例背景

案例名称：**设备巡检平台的一次回归准备与结果查看**。

你扮演测试工程师，先建立一个自己的体验项目，分别载入 Excel 和平台 JSON 演示数据；再进入预置的“设备巡检演示”项目，查看查询用例、冻结任务、版本关系和待澄清原因；最后查看一条已有适用脚本的演示运行、失败差异、截图与录像。

本指南只使用 UI-D1 原型和独立演示数据。所有项目、用例、任务、脚本、运行和媒体都是演示对象，不会启动 Harness、模型、Playwright 业务脚本，也不会修改正式后端、真实项目、候选、首审或历史证据。

建议按 A → B → C 连续体验，中途不要点击“重置演示”。完整走完约需 15～25 分钟。

## 2. 启动与入口

在仓库根目录打开 PowerShell，运行：

```powershell
node workbench/ui-prototype/serve.mjs 4311
```

看到以下文字后，保持这个 PowerShell 窗口开启：

```text
UI_D1_PROTOTYPE_READY http://127.0.0.1:4311
```

浏览器打开：<http://127.0.0.1:4311/#/projects>

正常首页标题是“所有项目”，顶部有“交互原型 · 演示数据”，项目卡片中应看到“设备巡检演示”“告警中心演示”“导入格式验证”和“空项目示例”。若 4311 已被占用，不要关闭未知进程；先打开上述地址确认是否正是这个页面。若不是，可把启动命令和浏览器地址中的端口同时改为 4312。

## 3. 本次只关注的对象

| 类型 | 具体名称 | 用途 |
|---|---|---|
| 你创建的项目 | 我的UI体验项目 | 体验多来源导入、重复识别和真实 JSON 下载 |
| 预置项目 | 设备巡检演示 | 120 条合成用例的密度项目；路线 B、C 均在这里 |
| 查询用例 | DEMO-Q-001 · 列表查询核对 | 查看完整正文、创建尚未启动任务、冻结 v1、形成 v2 |
| 已有适用脚本用例 | DEMO-S-001 · 设备排序与分页 | 明确触发演示运行，查看成功与失败记录及媒体 |
| 待澄清用例 | DEMO-C-004 · 任务名称字段范围确认 | 查看缺少逐步预期、禁用建例及处理主体 |
| 预置失败记录 | 受控反例验收 · 断言不符 | 查看预期/实际差异，以及后续步骤“未执行” |

不要在 120 条用例中逐页寻找。进入“设备巡检演示”后，直接在“搜索用例”中输入上表编号。

## 4. 路线 A：准备项目与导入

开始前，在首页右上角点击一次“重置演示”，回到 4 个预置项目的初始状态。

| 步骤 | 在哪里点击 | 应该看到什么 |
|---|---|---|
| A1 | “所有项目”页 → “新建项目” | 弹出“新建项目”，说明创建结果只写入当前浏览器会话。 |
| A2 | 项目名称输入“我的UI体验项目”；说明可填“设备巡检平台的一次回归准备与结果查看” → “创建项目” | 自动进入空的“用例库”；左侧显示 0 条用例，并提示可以载入 Excel 或平台 JSON 演示包。 |
| A3 | 页面右上“导入用例” → 保持“Excel · .xlsx” → “载入Excel演示场景” | 进入“工作表与字段映射”；工作表为“用例”，编号、标题、模块、步骤和逐步预期均已有映射。这里载入的是预置场景，不是上传或解析任意 Excel。 |
| A4 | “生成演示预览” | 预览统计为：新增 2、重复 1、同源版本冲突 1、待澄清 1、不能导入 1。表格逐条显示动作、逐步预期和原始位置。 |
| A5 | 查看 `DEMO-Q-001` 的“处理决定”，保持“跳过，不覆盖” → “确认导入2条” | 显示“演示导入完成”：新增 2 条，另外四类问题各 1 条；项目计数变为 2。 |
| A6 | “继续导入平台演示JSON” → “载入JSON演示场景” | 显示 Schema `workbench/case-package-v1`、文件 `demo-platform-cases.json`，并明确“不执行任何代码”。 |
| A7 | “生成演示预览” → “确认导入2条” | 首次 JSON 预览为新增 2、重复 1；完成后项目总数变为 4 条。 |
| A8 | “再次载入同一JSON包” → “生成演示预览” | 统计变为新增 0、重复 3，“确认导入0条”可用；说明相同包不会再次新增。 |
| A9 | “确认导入0条” → “返回用例列表” | 返回“我的UI体验项目”，列表中有 `DEMO-X-101`、`DEMO-X-102`、`DEMO-J-201`、`DEMO-J-202` 共 4 条。 |
| A10 | 勾选 `DEMO-X-101` 和 `DEMO-X-102` → 浮动条“导出选中” | 弹窗说明将导出 2 条，格式为 `workbench/case-package-v1`，并标记 `demo_only=true`。 |
| A11 | “下载演示JSON” | 浏览器收到一个真实可下载的 JSON 文件。文件只含所选演示用例内容，不含脚本、审批、媒体或绝对路径。 |

## 5. 路线 B：理解用例、任务与版本

这条路线要从“我的UI体验项目”切换到预置项目，不要把刚才导入的 4 条用例当成查询用例。

| 步骤 | 在哪里点击 | 应该看到什么 |
|---|---|---|
| B1 | 左侧或顶部“所有项目” → “设备巡检演示” | 进入含 120 条合成用例的项目，用例库摘要显示 120 条。 |
| B2 | “搜索用例”输入 `DEMO-Q-001` → 点击“DEMO-Q-001 列表查询核对” | 用例 v1 的“用例内容”页；能看到前置条件、测试数据和 3 组逐步对应的操作/预期。测试数据的期望记录为 3 条。 |
| B3 | 页头“创建建例任务（演示）” | 弹窗明确“创建只冻结输入，不会启动模型”，来源为 `DEMO-Q-001@v1`，并列出将冻结的 3 个步骤。 |
| B4 | “创建任务，尚不启动” | 进入“建例任务详情”；当前结论是“任务已创建，尚未启动”，候选生成、技术验证、人工核对和脚本登记均未开始。 |
| B5 | 向下查看“任务冻结输入快照” | 来源仍是 `DEMO-Q-001@v1`，内容哈希为 `DEMO-Q-001-V1-A3F991`，测试数据仍是“期望记录：3条”，3 个动作和预期完整保留。 |
| B6 | “返回来源用例” → 页签“用例内容” → “编辑当前版本（演示）” | 出现“编辑用例v2（演示）”；页面说明保存新版本不会改变旧任务快照。 |
| B7 | 只把“测试数据”中的“期望记录：3条”改成“期望记录：4条（体验修改）” → “保存为v2” | 自动进入“版本与来源”；同时看到“用例v2 · 当前”和“用例v1”。 |
| B8 | 在“用例v1”一行点击“查看” | 页头是 `DEMO-Q-001 · 用例v1`，测试数据仍为“期望记录：3条”，没有被 v2 覆盖。 |
| B9 | 页签“建例任务” → 对状态为“任务已创建，尚未启动”的任务点击“查看任务” | 旧任务仍显示 `DEMO-Q-001@v1`、旧哈希和“期望记录：3条”。不要进入旁边的预置“要求待确认”任务来代替本次新建任务。 |
| B10 | “返回来源用例” → “返回用例库” → 搜索 `DEMO-C-004` → 打开“任务名称字段范围确认” | 内容状态为“存在待澄清项”，自动化状态为“验收范围待确认”；页头按钮为禁用的“暂不能创建任务”。 |
| B11 | 查看正文和禁用按钮提示 | 前置条件说明由“测试负责人”确认验收字段范围；第 1 步预期明确显示“缺少预期，不能创建可执行任务”。这就是暂不能建例的原因和下一处理主体。 |

## 6. 路线 C：查看运行与失败现场

路线 C 使用 `DEMO-S-001` 的预置已首审脚本。它与路线 B 新建的“尚未启动”任务是两个独立对象，不能互相替代。

| 步骤 | 在哪里点击 | 应该看到什么 |
|---|---|---|
| C1 | “返回用例库” → 搜索 `DEMO-S-001` → 打开“设备排序与分页” | 状态分别显示“内容已确认”“已有适用脚本”“已首审且适用当前版本”。 |
| C2 | 页签“脚本版本” | 脚本 v1 的状态是“已首审且适用”，适用范围是原型的无登录合成场景；右侧有“演示运行”。 |
| C3 | “演示运行” → 阅读弹窗 → “明确触发演示运行” | 弹窗明确不会启动真实 Playwright；确认后新增“手动演示回归”记录，并进入结果详情。 |
| C4 | 依次点击左侧 3 个步骤 | 新建记录整体为“通过”；每一步都显示自己的检查说明、预期和实际。 |
| C5 | 点击“页面截图”的缩略图 | 弹出“演示截图原图”，并明确这是合成媒体、非真实测试证据。关闭弹窗继续。 |
| C6 | 在“本次完整执行录像”点击播放，再点击暂停，并拖动底部进度条 | 录像可以播放、暂停和改变进度。它只有完整运行录像，没有步骤时间戳；点击左侧步骤只切换检查说明，不应让录像自动跳到某一时刻。 |
| C7 | 页面上方“同一用例的记录” → “受控反例验收 · 断言不符” | 整体状态变为“断言不符”，但第 1 步仍是“通过”、第 2 步是“断言不符”、第 3 步是“未执行”。 |
| C8 | 点击第 2 步“按创建时间降序” | 预期为 `EQ-106、EQ-104、EQ-102`，实际为 `EQ-102、EQ-104、EQ-106`，并显示原始差异摘要。 |
| C9 | 点击第 3 步“切换到第二页” | 状态和实际都明确表示“未执行”，没有因为前面出现过通过步骤而被画成通过。 |
| C10 | “返回执行记录” | 项目执行记录列表同时保留新建的“手动演示回归”、预置正常回归、受控反例和其他异常演示记录。 |
| C11 | 顶部“设备巡检演示” → 搜索并打开 `DEMO-S-001` → 页签“执行历史” | 用例自己的历史中可并列看到“手动演示回归 · 通过”“正常回归 · 通过”“受控反例验收 · 断言不符”。 |

## 7. 恢复初始演示状态

点击任意页面右上角“重置演示”。重置后会回到“所有项目”，恢复 4 个预置项目及其初始演示用例、任务和运行记录。

重置会清除**当前浏览器标签页会话**中的以下演示修改：

- “我的UI体验项目”及其中导入的 4 条演示用例；
- 你创建的尚未启动任务；
- `DEMO-Q-001` 的体验修改 v2；
- 你明确触发的“手动演示回归”记录；
- 搜索、筛选、勾选和当前步骤等界面状态。

重置不会删除浏览器已经下载到本机的 JSON 文件，也不会修改仓库文件、正式工作台或任何真实数据。要重新体验，从路线 A 的 A1 开始即可。

## 8. 模拟操作与真实文件

| 项目 | 性质 |
|---|---|
| 新建项目、Excel/JSON 导入、用例编辑、建例任务、脚本运行、运行结果 | 浏览器会话内的模拟操作；刷新后仍在当前标签页会话中，点击“重置演示”后清除 |
| Excel 场景 | 预置确定性夹具；没有上传或解析任意用户 Excel 文件 |
| 平台 JSON 导入包 | 预置演示包；不会读取用户文件或执行其中代码 |
| 截图与 WebM 录像 | 本地合成演示媒体；不是业务执行证据 |
| “下载演示JSON” | 真实浏览器文件下载；文件内容来自当前页面所选演示用例，含 `demo_only=true` |
| Harness、模型、业务脚本、正式后端写接口 | 全程不调用 |

当前 Codex 沿用既有配置；具体子型号和推理档位在本体验页面中不可取得，记录为未知。
