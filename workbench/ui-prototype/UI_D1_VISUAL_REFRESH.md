# UI-D1 冷白／靛蓝视觉修订

日期：2026-09-22。起始提交：`0655dc23f77b3ad9aa92c820c535d6352562da42`。

## 目标与边界

用户在原型交互一致性收尾后要求重新设计，并明确不再沿用砂岩陶土配色。本次只修改独立 `workbench/ui-prototype`；停止于原型待用户确认。正式页面、后端、真实数据、历史报告和原有演示媒体均未修改。Harness、建例模型和业务脚本执行均为 0。Codex 配置未更改，具体子型号与推理档位未取得，记录为未知。

## 变化

- 冷白内容面、浅灰背景、深蓝灰正文、靛蓝主操作；降低边框和标签的视觉重量。
- 项目页改为概览与项目卡片，保留搜索、创建和进入项目；用例库保留表格，筛选收为单行。
- 修正通用输入样式影响复选框、图标默认实心、状态圆点重复及编号／标题／来源混排。
- 用例的四类状态并排展示；动作和预期按步骤成对展示；任务的阶段与分层结果分别保留。
- 结果页并列预期／实际、截图／录像；只有实际断言不符的区块使用错误背景。修正图片固定高度造成的留白。
- 切换页面回到顶部，不继承上一页滚动位置。原版本快照、下载和状态判定逻辑不变。

## 实际验证

`node --test workbench/ui-prototype/prototype.test.mjs`：退出码 0，9 项通过，无跳过。包含原版本快照、阶段映射、选中／全部导出内容的回归；配色断言按新的用户要求更新。

通过真实 Chromium 完成以下原型检查，均只使用合成演示数据：

- 项目卡片进入用例库；搜索和三类筛选控件位于同一行。
- Excel 演示场景 → 映射 → 六条预览 → 确认新增两条 → 返回列表，数量由 120 变为 122；继续进入原生包预览。
- 用例详情 → 关联建例任务 → 待处理问题，冻结输入与范围待确认状态仍展示，不变为批准。
- 执行记录 → 失败步骤，预期／实际和错误文本显示；截图真实加载、原图弹窗可打开关闭；录像资源就绪且时长 3.64 秒。本次不新增录像播放控制专项结论，不将媒体加载等同于重新执行测试。
- 六屏分别在 1440×900、1920×1080 读回，页面无横向溢出；截图、任务阶段、列表与详情的代表性渲染已目视核对。

未重跑历史完整验收、业务用例或模型任务。六张截图证明本次原型显示，不证明正式工作台接入或产品验收。原验收与一致性修订报告继续保留。
