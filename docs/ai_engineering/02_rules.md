# 02 工程规则

## 结论

本文档记录 `通用 Web UI 测试 Agent · v0.3.0` 的工程规则初稿。已有根规则文件优先保留；本文件只补充 AI 工程治理入口。

## 已发现规则来源

- `AGENTS.md`
- `CLAUDE.md`

## 通用规则

1. 优先遵循项目已有技术栈、目录结构和命名风格。
2. 不主动引入新框架、新构建系统或大规模重构。
3. 修改公共接口、协议、配置或数据结构时，同步调用方、测试和接口文档。
4. 不提交密钥、账号、生产地址、日志、缓存或临时文件。
5. 不自动执行 `git commit`、`git push`、`git tag` 或发布操作。

## 项目规则

1. 当前规则来源：AGENTS.md, CLAUDE.md。
2. 源码目录线索：src。
3. 测试目录线索：tests。
4. 构建配置线索：package.json。

## 高风险文件或目录

| 路径 | 风险 | 修改要求 |
|---|---|---|
| `.github/` | CI、发布或自动化流程可能受影响 | 修改前确认触发条件和权限 |
| 配置、密钥、环境变量相关文件 | 可能包含敏感信息或生产差异 | 不写入真实密钥，改动前人工确认 |

## 文档同步规则

1. 项目目标变化：更新 `00_project_brief.md`。
2. 架构或模块边界变化：更新 `01_architecture.md`、`07_code_model.md` 和相关模块文档。
3. 接口、协议、配置变化：更新 `03_interfaces.md`。
4. 构建、测试、部署变化：更新 `04_build_test.md`。
5. 新增可复用经验：更新 `docs/reusable/`。
