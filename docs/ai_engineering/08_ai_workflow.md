# 日常工作流与正式交付

## 自动按影响处理

每次任务由当前 Agent 在同一轮内静默分流；不启动第二个 Agent，不输出分类表，不为判断加载完整 Skill或扫描整库。

- 轻量：只读咨询；注释、错字、无业务含义的展示和排版；外部行为不变的内部重构；补充已有行为测试；期望明确、影响局部的低风险修复。直接修改并做适当验证，不建 FIX/REQ。
- 正式：新增或改变业务规则/验收、公开接口或配置语义、跨模块契约、权限安全、金额审批、数据迁移或删除、依赖构建部署、关键并发，或用户明确要求正式交付/完整闭环。自动创建或复用与当前任务直接相关的真实 REQ，再读取正式流程。
- 不触发：修改行数或文件数、缺少自动化测试、项目存在历史 REQ/FIX/治理脚本/正式门禁，均不能单独触发正式流程；不把无关的已有需求追加为当前任务记录。
- 待确认：只有未知信息会阻塞当前请求阶段时才问一个必要问题。设计/任务拆分阶段把未决业务语义写成互斥待确认分支并继续；进入代码实现或确定测试判定前，影响允许/拒绝、成功/失败或业务验收的未知项必须确认。
- 范围扩大：执行中首次发现实际影响命中正式条件时，允许重新分流一次；否则不重复判断或追加治理步骤。

## 读取与输出

小任务只读相关代码、规则及测试。开始最多一句行动说明，结束简述修改、实际验证和必要限制；不展示内部分类过程或冗长计划。
轻量任务只修改目标代码和必要测试。仅当用户或项目明确要求留档、或问题确需后续追踪时才更新 docs/changes/daily.md；项目事实未变化时不更新模块或环境文档。轻量任务不运行状态同步、证据收集和全项目交付检查。

## 正式流程

自动选择或创建与当前任务直接相关的真实 REQ，维护需求、设计、任务、验证和追踪。REQ-0000-template、未确认 legacy 和无关的已有需求不能作为当前任务记录。
首次只读需求索引，并用一次限定在 `REQ-*/current_state.md` 的检索查标题、模块或行为关键词；分类阶段禁止搜索其他 docs、历史需求全文、归档、legacy 或交付证据。直接相关的活动 REQ 存在时复用；没有时优先用 `scripts/create_requirement.py` 一次创建并登记骨架。脚本不存在时只能整目录复制模板并批量替换编号，禁止读取或枚举模板内文件；无法复制时停止说明。
创建骨架后只读取和填写当前阶段需要的文件。无关问题不展开、不修复、不汇报，除非它直接阻塞当前任务。达到用户要求的阶段边界后停止。
只做设计/任务拆分时，默认发现预算为 1 次索引、1 次 `REQ-*/current_state.md` 检索和最多 6 个直接相关实现文件；不读取生成器、模板、无关 REQ、模块索引、构建文档或交付脚本。设计内容默认不超过 1 个 UN、5 个 DR、5 个设计决策、5 个任务和 5 个 VT；不运行测试或正式门禁，写完即停止。
旧 FIX-* / fix-record-v1 保持兼容，仅在选择正式 Quick Fix 交付时使用原资格和真实单元/集成测试要求；不把既有正式 FIX 自动降为轻量以绕过未通过的门禁。
正式交付前逐任务根据实际实现证据填写状态；JSON 包只编辑事实源，sync 仅据此渲染视图，不从测试结果推断任务已实现。旧 Markdown 包逐项直接更新状态。已执行 VT 的 current_evidence 使用包含 command、exit_code、test_count、failure_count、skipped_count、log_path 的对象；设计阶段可保留文字说明。正式交付按顺序运行 scripts/sync_requirement_status.py、scripts/collect_delivery_evidence.py、scripts/check_ai_context.py，选择当前记录并记录实际命令与退出码。项目中的完整正式规则只在该阶段读取。

## 状态边界

未运行、无法运行、仅静态检查、编译通过、单元测试通过、集成测试通过、人工待确认分别记录，不互相替代。
scripts/check_ai_context.py --installation-only 只检查完整安装入口和脚本结构，不检查业务变更、需求覆盖或交付证据，也不能作为 collector/正式门禁的替代。仅更新根目录规则块时，使用 Skill 的 upgrade_project_rules.py --mode check；不要求旧正式脚本具有新版安装参数。
不自动 commit、push、tag 或发布。升级允许备份后替换 Skill 受管规则；保留用户内容与项目事实。
