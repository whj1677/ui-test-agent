# 可选探索交互说明

作用是让探索器在确定无业务写入的控件上，尝试查询文本或下拉选项并采集相关页面变化。这份文件不定义业务预期，不授予提交、保存、删除权限；不导入也可以使用普通导航探索。

前端技术审查人员应检查具体页面上的 input/change、自动保存、GET/POST 请求和本地存储处理，再为必要控件编写说明。不能只凭控件名称、HTML 类型或模型声称来判断安全。页面实现改变后必须重新审查。

测试人员从控制台下载本轮用例基线，将其交给技术人员。技术人员导出的文件可通过“导入探索交互说明”导入，需包含：

```json
{
  "schema_version": "ui-agent-discovery-contract/v1",
  "baseline_sha256": "本轮基线文件的SHA-256",
  "interactions": [
    {
      "case_id": "CASE-001",
      "entry_path": "/items/",
      "locator": {"kind": "testid", "value": "item-search"},
      "operation": "fill",
      "values": ["原用例中的查询词", ""],
      "evidence": {
        "kind": "source_review",
        "ref": "源码文件、版本/摘要及已核对的事件处理位置",
        "no_business_write": true
      }
    }
  ]
}
```

- `entry_path` 绑定页面路径、查询参数和 hash。相同控件标识在其他页面不会沿用该说明。
- `fill` 每个控件最多 3 个值，每值最多 200 字符，必须来自该用例的操作描述或测试数据；显式空串允许清空。敏感输入不允许探索。
- `select` 每个控件最多 8 个值，填写 DOM 的 option.value；执行时必须仍属于当前启用选项。候选同时显示选项文本。
- 模型只返回当前候选 ID，不能自行添加值、定位器或代码。旧候选在页面/控件状态变化后会被拒绝。
- 控制台保留观察路径与来源；“采集结束”不等于计划已审核或业务断言满足。后续计划仍需审核。

无业务写入是操作者提供的技术声明，程序校验其结构、用例和路径绑定并拦截未授权写请求；它不是对所有任意脚本副作用的自动证明。
