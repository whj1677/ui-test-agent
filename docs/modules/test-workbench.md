# 测试工作台第一阶段模块

本模块对应 `REQ-0020`，在 `workbench/` 中提供本机单用户的批准脚本执行闭环。它独立于原产品 `src/`、`public/`、旧服务和旧运行数据，仅执行已经登记、已有真人批准依据且字节哈希匹配的排序脚本资产。

## 职责与边界

- 登记确定版本的原用例、批准脚本、批准依据、配置摘要、依赖锁和允许环境。
- 从 Web 选择固定的 `normal` 或 `fault` 入口，启动一个独立 Playwright Test 子进程，并支持停止本任务拥有的进程树。
- 按运行目录持久化进程事实、结构化报告、步骤、错误和媒体索引；服务重启后读取历史，并把遗留活动状态收敛为中断，不自动重放。
- 依据进程、报告、目标测试和证据完整性分别判定；断言失败默认归因 `PENDING_ANALYSIS`，不自动宣布产品缺陷。
- 不调用 LLM、Claude Code、DeepSeek Harness 或 healer，不生成、修订或任意上传业务脚本，不提供多用户、远程执行或通用命令能力。

## 目录与数据

- `workbench/server/`：HTTP API、资产登记、JSON 持久化、报告解析、媒体边界和受控执行器。
- `workbench/web/`：只读取真实 API 状态的中文页面；不执行报告中的不可信 HTML。
- `workbench/tests/`：工程测试、浏览器冒烟、真实组合验收和重启历史核查。
- `workbench/.local/`：Git 忽略的本机目录，保存资产目录、逐次运行记录、Playwright 报告和媒体；每次运行使用独立目录，以临时文件加安全替换方式串行写入 JSON。
- `workbench/docs/`：可公开的脱敏验收报告与截图，不包含原始 Trace、视频、会话或凭据。

资产记录包含 `asset_id`、`case_id`、版本、来源提交、脚本 SHA-256、批准依据、配置/锁摘要及允许环境。运行记录包含 `run_id`、资产版本、环境、各时间点、执行/报告/测试/证据状态、退出码、错误、步骤和媒体索引。

## 本地接口

服务默认仅监听 `127.0.0.1:4210`。读取接口提供健康、资产、运行历史、单次详情和已登记媒体；JSON 状态变更接口提供受控登记、启动和停止。启动请求只接受登记资产与 `normal`、`fault` 两个环境标识，拒绝自定义 URL、命令、脚本路径和执行参数。状态变更限制为同源本地 JSON 请求，不开放任意跨域调用。

媒体读取先核对附件属于目标运行，再校验真实路径仍位于该运行目录内，并复核登记的大小和哈希；不提供任意磁盘文件读取。页面文本使用安全文本节点渲染。

M3-B2 项目用例任务复用既有 build task、生命周期和候选执行器。单次授权与项目、内部用例、版本、内容哈希和固定环境绑定；Harness attempt 读取冻结输入而非项目最新版。正常/反例报告和媒体由执行流程直接登记到同一任务，Web 媒体接口只接受该任务已登记的 screenshot、video、trace 文件 ID，并复核路径、大小、哈希及视频 Range。历史 `INPUT_ONLY` 任务不因该授权改变。

新建项目用例任务的模型可读输入使用 v2 快照，不再携带工作台反例验证契约。完整契约仍随任务持久化供控制器在候选生成后执行正常/反例验证，但不会写入 `task.md`、`case-snapshot.json`、实际 Agent 指令或 attempt 的其他初始模型输入。历史 v1 任务按原字节读取，其已有运行事实不变，也不追溯声称反例曾被保密。

M3-C 增加 `HUMAN_FIRST_REVIEW_PASSED_SCOPED` 资产：登记器必须同时核对源任务、候选原件、限定首审记录和项目用例版本，随后把候选与首审记录按原字节保存到私有 `data/assets`。执行器按资产决定脚本文件名、入口变量、步骤与配置；限定资产使用 `PROBE_URL` 和 workbench Playwright 依赖根，不伪装为旧排序资产。正常环境属于产品入口，错误输出反例只属于受控验收入口。

E2E-01 执行详情由 `workbench/web-v2/` 展示。带 `run_id` 的详情链接必须精确命中当前项目记录；空、非法、不存在或跨项目 ID 仅显示错误，不回退到最新运行。字幕时间轴只有在唯一页面身份、Trace 截图与已编码 WebM 解码帧匹配并满足相邻步骤精度门槛后才允许定位；旧版字幕仍可播放，但未校准记录禁用步骤跳转。独立本机视觉校准只验证时钟映射机制，不等同于六条产品录像已经具备精确定位证据。

E2E-01 录制判定当前版本 `e2e01-caption-timeline-v3` 还要求视觉锚在录像时间上唯一：同一 Trace 画面在相隔至少 80ms 的多个解码帧上同样匹配时，不用其中任意一个猜零点。少于 3 个无歧义锚、步骤精度跨相邻边界或本次媒体不足，均保留原业务结果与原视频，但不生成新的字幕交付版、不开放步骤跳转。健康诊断报告正在运行的版本；旧字幕运行器的记录不能被新版准备门禁误认。详情组 TC-003/006 的 v2 新运行已经证明短步骤、重复/静止画面和少量 Trace 帧会阻断产品级定位；具体运行与媒体证据见 `workbench/docs/E2E_01_CAPTION_SELF_TEST.md`，其余组未因隔离校准成功而直接重录。

AUTH-01 新增被测系统登录准备页，仅配置独立本机合成站。工作台服务在内存持有非持久浏览器上下文，按项目、环境、角色和会话版本核对服务端身份；锁定 DSH Browser 插件以 CDP attach 观察登录后的专用上下文，候选执行器通过限时本机内存通道取得认证状态并建立新的 Playwright 上下文。真实 Harness 合成站验证已完成，登录输入阶段不启动模型或媒体。现有六用例任务仍是无登录环境，`BuildTaskManager` 尚未把此状态绑定至项目建例/试跑；执行中失效和运行记录认证阻塞也尚未接通。具体范围与缺口见 `workbench/docs/AUTH_01_SELF_TEST.md`。

后续方案变更为 `e2e01-step-evidence-replay-v1`：试跑仍保留原始连续录像，并在同一 Playwright Test worker 的 `test.step` 回调内有序采集开始前、结束后或失败后截图；截图失败单独记证据异常，不改原业务结果。按本次步骤截图、冻结用例和报告实际结果生成独立的中文步骤证据回放，章节使用合成视频自身时间，页面和视频均明确标注“非原始连续录像”。旧 Trace/WebM 时间映射不作为回放前提，也未因此修复原录像的精确步骤定位。2026-09-24 目标 4322 服务已加载 v1；修复 Windows 长路径下子进程 cwd 失败后，工作台新增最终六条产品记录，三条正常通过、三条指定业务差异失败，六套步骤回放经浏览器核对。候选仍待人工批准；最终六条后的服务重启读回未验证，详见同一自测报告。

## 执行约束与状态

- 执行器通过已锁定依赖中的 Playwright CLI 和参数数组启动，`shell=false`、`workers=1`、`retries=0`。
- 沿用批准配置的 Chromium、语言、视口、测试期限和断言期限；适配配置只改变 base URL、Reporter 与本次独立输出位置，并单独记录差异。
- 每次运行前后核对批准源与运行副本 SHA-256；任何未批准或不匹配资产均拒绝。
- 子进程仅获得必要的固定环境变量，不继承模型密钥、Cookie、令牌或完整宿主环境。
- 同时最多一个活动运行；停止只针对当前工作台记录并拥有的进程树。
- Web 环境选择由前端状态持有；轮询重建允许项后恢复有效选择，启动请求使用该状态。只有选择不再属于当前资产允许环境时才回退。
- 原始 Playwright 通过事实与整体有效通过分开保存。`complete_pass=true` 只允许 `PROCESS_ENDED` 正常终态再叠加退出码、报告、目标测试、跳过、步骤及 screenshot/video/trace 三类既定媒体齐全条件；哈希异常、取消、中断、进程、报告或证据异常均保持整体不通过。
- 错误事实只在同时解析到具体期望值和实际值时认定 `ASSERTION_MISMATCH`；缺元素、严格匹配冲突、单侧值、纯超时分别保留定位、未决断言或超时类型，归因仍为 `PENDING_ANALYSIS`。
- 登记步骤清单与报告中的实际步骤分别保存；失败后的后续步骤显示“未执行”，不依据终态补猜。
