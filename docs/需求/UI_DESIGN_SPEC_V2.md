# 测试工作台 UI 设计稿与实施规范 V2.0

日期：2026-09-25  
交付性质：面向测试人员的目标界面设计、可点击交互稿、Codex实施约束和验收规范。不是现有产品完成证明。

**核心决定：以“项目 → 用例 → 本次结果”作为日常主线；以“测试批次”保留回归范围与历史。生成脚本和运行脚本必须是两个明确不同的操作。**

## 0. 如何使用本设计包

| 文件 | 作用 |
|---|---|
| `index.html` | 可点击多页面设计稿，CSS、JS、示例图像及MP4均内嵌；不需要npm、不需要启动工作台、不请求后端 |
| `screens/01…16-*.png` | 页面及关键对话框的浏览器实际渲染图，不是产品运行截图 |
| `DESIGN_OVERVIEW.png` | 四个关键界面总览；精读以单屏原图与HTML为准 |
| `UI_DESIGN_SPEC_V2.md` | 本文：页面、行为、状态、版本和验收规则 |
| `CODEX_IMPLEMENTATION.md` | 可直接交给Codex的实施入口；不得把原型演示数据当正式实现 |
| `DESIGN_QA.md`及JSON | 本设计稿实际检查结果与未实现范围；不冒充真实后端验收 |

### 0.1 依据、优先级与待确认项

依据本对话已确认的原需求和《UI_TEST_WORKBENCH_USER_WORKFLOW_REQUIREMENTS_v1.0.md》，保留《UI_WORKFLOW_PHASE1_CASE_DETAILS_AND_RERUN.md》的历史、数据和执行边界。本V2细化页面与交互，不取消原有报告、媒体、脚本维护及删除旧UI需求。

优先级：用户明确确认的业务需求 > 本文行为规范 > 页面图。图上空间简化不能取消规则；原型的演示限制不能反向变成产品限制。

- **已确定**：墨白/石墨灰的桌面工具风格；Excel为主要用例入口；用例详情整合结果；单条/选中/项目复跑；脚本重新生成；中文字幕媒体；报告导出；移除旧产品UI。
- **本设计提出的组织方案**：单套项目导航、四个用例详情页签、串行测试批次、统一运行前检查、脚本维护确认框、报告预览页。属于设计建议，不是用户逐字指定。
- **唯一当前需要用户拍板的格式问题**：主报告要Word、PDF还是离线HTML。本稿用离线HTML演示，其他格式不得假设已经确认。先实现与格式无关的报告快照/明细数据；不要为了未知格式一次开发三套导出器。
- 首次核对和技术试跑沿用现有产品权限边界。本设计不擅自取消核对，也不新增多人审批平台。

### 0.2 设计示例与真实资料分开

原型中的`CASE-001…024`、V1.8.x、已核对状态、批次和示意媒体均为设计数据，不是历史KC用例的实际结果。完整媒体布局重点展示`CASE-023`；其他用例不借用这份画面。示例的状态和计数不能作为真实项目验收材料。

实际报告里“18个独立执行PASSED，14个原要求完整、3个偏离、1个前置待核对；另外6个未独立执行”必须由实际来源记录呈现。不得用本稿的24/18/15/3/6示例数据替换，也不能伪造一次历史完整批次。

设计稿顶部的“示例数据/不连接后端”、页面目录、示例下载提示、完成态预览按钮仅服务设计评审。正式上线时移除这些演示控件；保留业务上必需的失败、核对、权限与媒体来源说明。

## 1. 信息架构：一套导航，不再重复

### 1.1 全局与项目空间

全局落点为“项目列表”。创建项目或进入项目后默认打开用例库，不打开执行日志。

项目内仅一套左侧导航：

```text
← 全部项目
当前项目名称

用例库
测试批次
报告
环境与登录
项目设置
```

顶部保留产品名称和必要的工作空间信息。不再同时展示重复的项目Tab导航。不将“自主建例”“Harness”“attempt”“Run列表”列为测试人员主导航。

“脚本生成详情”是从某条用例或一组生成操作进入的二级页面。内部任务仍完整保存，可以在技术详情追查，不删除。

环境与登录可由侧栏维护；运行确认框和生成确认框也显示本次环境/角色及就绪状态。不要让用户为了登录而丢失当前用例和运行选择。

### 1.2 对象关系，不得混用

```text
项目
 ├─ 用例 → 不可变内容版本
 │    ├─ 自动化脚本 → 候选/已核对等资格 → 完整文件包版本
 │    └─ 该用例的各次运行结果 → 绑定具体批次、环境、版本及媒体
 ├─ 测试批次 → 创建时冻结的计划清单 → 每项运行/未执行原因
 ├─ 环境/登录准备
 └─ 指定批次或运行生成的报告快照
```

被测软件版本、用例内容版本、脚本版本、测试批次和run是不同对象。软件从V1更新V2，本来就是复用脚本复测的情形；不能自动要求重新建例。用例正文改变后，也不能自动继承旧脚本适用性。

### 1.3 推荐深链接语义

路由可以适配已有工程，但必须等价保留以下上下文。以下是**目标路由语义，不是声明现有API已实现**。

| 页面 | 建议上下文 |
|---|---|
| 项目用例库 | project_id + 搜索/模块/筛选/页码 |
| 用例详情 | project_id + case_id + case_version + tab + 可选batch_id/run_id |
| 批次详情 | project_id + batch_id |
| 生成详情 | project_id + case_id + generation_task_id |
| 报告预览 | 固定report_scope + batch_id/run_id + 报告快照身份 |

指定对象不存在、跨项目或版本不合法时，显示错误及返回入口；不得静默回落到“最新记录”。前进、后退、刷新恢复明确上下文，不触发执行。

## 2. 视觉规范

### 2.1 风格与尺寸

不是营销Dashboard，不做渐变、玻璃卡片、巨大统计数字、AI星光图标或彩色全屏警报。用例表格与证据是主体；空白用于分组，不把所有功能做成堆叠大卡片。

| 项目 | 基准 |
|---|---|
| 桌面画板 | 1440×1000；补查1280×800、1920×1080 |
| 顶部产品栏 | 62px；原型额外30px设计提示不属于正式产品 |
| 项目侧栏 | 202px；较窄桌面180px |
| 主内容边距 | 基准32px；1280宽降至24px |
| 页标题/正文/辅助文字 | 24–26px / 13–14px / 11–12px；重要失败值不小于18px |
| 按钮/输入高度 | 36px为常用，紧凑辅助操作29–32px |
| 表格 | 表头约40px；带副信息的行56–64px；固定列名清楚，无大面积彩底 |
| 间距 | 4、8、12、16、24、32px；避免随意值遍布页面 |
| 圆角与阴影 | 表面6–8px；控件4–5px；仅弹窗/浮层适度阴影 |
| 字体 | 系统中文无衬线，Microsoft YaHei/PingFang SC等回退；不捆绑或要求下载字体 |

主题变量：背景`#F7F7F6`、白色表面、正文`#252525`、次要`#73736F`、分隔`#E2E3DF`、主按钮`#282926`。低饱和绿色仅表示执行通过/已核对，红色表示失败/不采纳，琥珀表示待处理。所有状态同时有文字/符号，不只靠颜色。

表格和主要操作在首屏可发现；详情第一屏先显示失败结论和证据区域，不先放几屏Run ID或历史索引。报告长页可以纵向滚动。1280宽不得因按钮挤压造成整页横向溢出；表格内容确需横向滚动时，只滚表格容器。

### P01 项目列表

项目名可点击，进入该项目用例库。新建项目只收集必要名称和说明，不要求用户先懂环境JSON、目录、授权ID。导入不同项目后数据独立；不能看到另一项目的脚本、选择集或运行结果。

### P02 用例库

顶部主操作：**导入用例、运行整个项目**。搜索与模块筛选紧邻表格；“导出用例”在表格工具条。无需新增一组铺开的逐用例结果卡。

表格列：复选框、编号、名称、模块、自动化脚本、最近执行、要求核对。标题/编号点击进入详情，复选框只做选择。可选整行非交互区进入详情，但按钮、复选框操作不得触发行跳转。

选中至少一项后显示选择操作条：已选N条、跨页保留、清空、生成/更新脚本、运行选中N条。**生成/更新脚本会调用模型；运行选中不会。**

- 表头复选框只选择当前页并明确标注；不伪装成全部项目。
- 跨页保留选择。筛选改变仍有筛选外选中项时，显示“已选N条，其中X条不在当前筛选中”，提供清除；不能偷偷扩大操作范围。
- “运行整个项目”始终表示整个项目，不等于当前页、筛选或选中集合。
- 未选择用例时不自动默认为全项目生成脚本。
- 默认结果视图可为各用例最近结果，但必须标注可能跨批次；不是全量回归统计。
- 对被拒绝候选显示“不采纳/需修订”。要求核对未知则显示“待核对”，不是已核对。
- 标题超长可截断并提供完整文本；禁止把UUID当用例名称。

### P03 导入向导

“选择文件 → 字段映射 → 原文预览与处理 → 完成”共四步。初次与重复导入共用流程。

Excel是测试人员手写用例的入口，原生包是跨项目复用入口。不同文件通过相应解析器进入同一用例库。不在此强迫生成脚本。

预览显示动作、预期、来源物理行/列、解析问题。保留小数、IP、单位、版本和中文。动作有而预期缺失可登记待澄清；预期没有对应动作则按已有契约拒绝，不能猜测配对。空行/列不能丢后续内容。

重复同源同版本不新增；同源冲突明确提示，用户选择追加新版本或独立副本，不静默覆盖。用户未确认前不写正式用例。确认入库后回到当前项目并定位导入集合。

原型不含Excel解析器；Codex必须复用已有真实上传、预览与确认后端，不能把示例预览函数复制上线。

### P04/P05 用例详情

固定头部包含：编号+标题、模块、用例版本、所选脚本及资格、单条运行、导出报告。内部身份折叠。

四个页签：**结果与证据、用例内容、自动化脚本、历史结果**。

默认行为：若明确链接带run/batch则展示该结果；无明确结果时有当前内容版本运行的用例显示结果页，否则显示正文与准备入口。只因页面轮询得到新结果，不自动切换用户正在查看的结果。

结果页顺序：
1. 当前批次/运行选择及所属软件版本、环境。
2. 原始执行结论、失败步骤、原预期/实际、未执行范围。
3. 如有要求偏离/前置待确认，显示独立核对说明。
4. 左侧步骤，右侧主要媒体；底部技术详情。

媒体选择和步骤选择不会跳到全局执行记录。运行单条后留在用例上下文，显示“本次执行中/完成”，并提供所属批次链接。返回用例库保留页码和筛选；从批次进入详情时提供“返回本批次”。

**绝不能显示“本次结果A + 上次录像B”。** 切换用例版本、run或batch时，步骤、错误、媒体、脚本身份一起更新；目标没有结果/媒体就显示缺项，不借用最新或别的用例。

正文页只读显示完整原文及源文件位置。编辑仅针对当前版本并形成新版本；历史正文只读。保存失败/并发冲突保留用户草稿并显示处理方式。

### P06/P08/P13 脚本维护与生成

三个明确操作：

| 操作 | 输入 | 输出与落点 |
|---|---|---|
| 运行已有脚本 | 指定版本完整文件包、环境与本轮部署身份 | 新批次/run；留在用例结果页；不调用模型 |
| 基于问题修订 | 原脚本+原要求+用户反馈/选定失败事实 | 新候选版本；进入生成过程；旧脚本保留 |
| 从头重新生成 | 当前确认用例+允许环境 | 不复用旧候选的全新候选；旧版不覆盖 |

确认框显示涉及用例数量、使用环境、反馈来源、预算上限、是否调用模型。预算来自实际配置和授权，不采用设计图里的20分钟/3次作为自动新授权。

对多条生成：先给预检与总体计划，允许串行，每条独立冻结用例版本。没有选中用例不能擅自生成整个项目；生成不能夹带业务预期修改。

生成过程默认展示已发生的阶段和简洁工具事实，例如观察、写稿、自测、修订、待核对；实际是可循环过程，不强迫每个任务都修订。任务内Coding Agent保持原有观察/调试自主权。禁止为了UI线性阶段重新限制API、helper或每轮要求人工批准。

不展示隐藏推理文本。原始技术日志按权限可查；不能把“模型正在思考”假进度当实际执行状态。取消保留草稿、预算与已执行事实。

新候选自测通过后，仍按既有核对要求处理。**新版本生成失败不覆盖旧版；运行绿色不等于自动批准；草稿改变后旧测试不能为新文件包背书。**

“核对通过”按钮的权限、适用范围和证据沿用已有后端；未有能力时明确未接入，不能前端一键修改approved字段。设计不扩建多人审批。

### P07/P09/P10/P16 运行与批次

单条、选中、整个项目使用同一个批次机制。首版串行执行即可，不引入定时/分布式调度。

运行前必须显示：请求N条、可运行M条、待处理K条，且N=M+K。阻塞原因逐项列出，不只显示数字。用户明确选择“仅执行当前可运行项”时，原请求清单和缺项仍进入批次；不自动调用模型补脚本。

被测软件版本/构建标识可填写或由环境事实取得，未提供则如实标注。版本变化本身不作废适用脚本。登录/可访问范围、数据初始化前提照常校验。

执行确认时冻结项目、请求范围、每个case_id+内容版本+内容哈希、脚本完整包身份、环境/角色、部署身份和许可范围。执行中的编辑或新候选不替换已冻结内容。

执行状态必须分为：等待、执行中、通过、未通过、阻塞、取消未执行。业务失败后继续无依赖用例；共享环境问题只阻塞受影响范围；运行中取消先停止后续调度，保留已完成事实。重启后中断批次不自动重放。

请求幂等：同请求双击/重发不启动两次；用户明确再次运行创建新批次。先预检与后确认之间条件变化时重新校验，不能复用过期预检直接执行。

批次详情展示计划、已执行、通过、未通过、阻塞/取消/未执行的分项，并可按状态筛选。计数来自实际数据，明确分母。详情内点击用例进入该用例且带入当前batch/run。

“重跑本批未通过”是选择原失败项后创建新批次。允许修改本次软件版本，默认复用选定脚本；不覆盖旧失败、不把未复测用例的旧通过拼入新报告。

历史独立任务未分批时标为“历史结果/来源未分批”。67个执行含开发自测和独立执行，不能事后声称是一个24条全部独立复验的批次。

### P11 报告

报告页不是复用“用例导出”。支持**指定测试批次报告、指定用例的指定运行报告**，可复用范围模型扩展选中条目导出。

预览在导出前显示固定范围和版本；导出成功必须提供真正文件，生成过程可取消/失败。报告内容绑定结果快照，后续执行不悄悄更新已导出的报告。

必需字段：项目、批次、部署版本、环境与账号角色摘要、计划/实际范围、版本关系、分项结果、要求核对、原错误与实际值、缺项、未执行步骤、媒体来源。无实际值写未取得，不能从预期或预置故障填充。

**当前报告格式待确认。** HTML示例必须可离线打开，图像内嵌或相对资源随包携带。可选视频/Trace附件时提示体积与敏感性，不能只导出指向本机localhost的“离线包”。不导出密钥、Cookie、会话令牌或未授权业务秘密。

报告中的“执行通过”“核对通过”“正式采用”三者分列，不给偏离原要求的绿色写成总体通过。

### P12/P14/P15 环境、设置、空状态

环境页让用户检查入口、角色、登录准备及当前会话状态；不要在普通页面曝光密钥、CDP地址、完整storageState。用户可在专用浏览器输入密码/验证码，不纳入业务录像或模型观察；状态以真实身份检查为准。

未登录、角色不符、会话过期、服务不可用分别说明。重新登录不自动执行先前有副作用的操作。未接通的AUTH能力不因显示登录按钮而声称已支持。

项目设置仅管理基本信息和必要配置。不增加企业级用户组织/权限设计。空项目突出导入入口；无脚本、无结果、无媒体各有独立空状态和下一步，不能是一整屏空卡片或JSON。

## 4. 状态规范：不能用一个“绿灯”替代所有结论

| 维度 | 示例状态 | 应用位置 |
|---|---|---|
| 用例内容 | 已确认 / 待澄清 / 输入不合法 | 正文、导入、运行前检验 |
| 脚本资格 | 未生成 / 生成中 / 待核对候选 / 限定试跑 / 已核对适用 / 需修订 | 用例表与脚本页 |
| 原始执行 | 未执行 / 等待 / 运行 / PASSED / FAILED / CANCELLED / BLOCKED | 本次结果与批次 |
| 要求核对 | 未核对 / 完整 / 原要求偏离 / 前置待确认 / 覆盖不足 | 结果补充结论 |
| 媒体 | 完整 / 缺截图 / 缺录像 / 缺Trace / 回放失败 | 媒体区及报告 |

这些是界面语义，不要求重命名现有所有后端枚举。建立显式映射，未知状态原样标注未知，不靠字符串includes判断“通过”。业务差异与脚本错误不得用页面颜色自行归因。

关键示例：KC-01/07/10原始执行PASSED但改变初始筛选，应保留PASSED同时显示“原要求偏离，不采纳”。6条只有开发自测的结果明确“尚无独立复验”，不能补造run。

核对记录必须有来源、所针对的内容/脚本包版本及时间。旧核对不自动附到新候选上；模型coverage只作为材料，不转为正式批准。

## 5. 媒体专项设计与验收

### 5.1 看得清，不只是输出了文件

- 新录像记录实际像素尺寸、测试viewport、缩放和编码参数；先检查采集是否发生下采样，再调整播放器。禁止只扩大低清视频。
- 建议采集尺寸显式匹配测试视口，常规桌面可从1280×720或1600×900进行验证，复杂表格必要时更高；这属于实施建议，不是用户已确认硬指标。
- 以实际关键字段、金额、状态和错误文本可辨认为验收标准，不只以分辨率、码率或扩展名验收。
- 暗色字幕放在专用字幕带，不遮挡业务字段。中文字幕包括步骤、动作/检查、状态；结果不能提前出现。
- 不再为历史缺失帧的录像反复开发拟合算法。旧资料无法补清晰时提示“历史录制清晰度有限”。

### 5.2 三类资料分别呈现

**步骤回放**：从本次实际采集的步骤画面组织，明确“非原始连续录像”；章节映射使用回放时间。

**原始录像**：保留原字节，真实连续过程。没有可靠时标时不声称原录像精确跳到业务步骤。

**截图/Trace**：截图可原图和放大；Trace实际下载并校验哈希。嵌入Viewer不是本轮必要条件。

缺哪类说明哪类，不拿不同run的素材填补。未执行步骤没有实际截图或视频片段。轮询不能重建video元素、重置播放位置、抢回用户选中的批次。

## 6. 数据与接口接线约束

Codex先核对当前真实代码，不照本文发明同名API，也不复写第二个执行器。已有候选包、自测、脚本生成、candidate-trials、媒体、用例导入和运行存储优先复用。

建议前后端视图模型包含以下概念（字段名可沿用既有契约）：

- CaseSelection：project_id、case_id、content_version、content_hash。
- ScriptSelection：script_version、bundle_manifest/hash、适用用例/环境、核对/试跑资格。
- Batch：request_id、scope、requested_items、frozen_executable_items、blocked_items/reasons、environment、software_build、状态与时间。
- Run：batch/item/source_task、case/script身份、原始结果、步骤、原错误、媒体索引、要求核对引用。
- ReportSnapshot：固定scope/result身份、生成时间、模板版本、附件清单/大小与缺项。

API报错给出业务可理解的原因、具体对象和下一步，不返回只让用户读堆栈的500页。服务端实施身份/许可校验；前端禁用只是提示，不是安全边界。

从主页面查询只读结果不会开始Harness、重跑测试或写新的执行次数。技术试跑和正式运行由现有许可区分；不足的后端功能要补接，不得用toast成功、模拟进度、sessionStorage业务数据替代。

本机数据目录及旧历史资料保持独立；不为新UI重新搬项目、改端口或合并现有数据库。公开交付不包含`.local`、密钥、会话或私有媒体。

## 7. 旧工作台移除

最终只保留新产品UI，不长期维护“旧版/新版”两组导航、两条写入路径。旧地址可以重定向到对应新对象，或显示迁移说明。

在移除前建立旧功能→新落点清单并实际验证。删除旧UI专属资源、旧导航与重复入口；共享服务器、执行器、媒体代码、历史数据、脚本包、账本、Git历史及公共`.git`不删除。不要仅靠隐藏菜单声称旧UI移除完成，也不要按目录名一刀切删后端。

## 8. 交付验收：按真实用户旅程

由Codex先测试后交付，不要求用户做第一轮找Bug。使用实际后端与独立验收项目，旧24条资料仅只读关联；产品失败不会让UI验收自动失败，但必须真实显示。

| 编号 | 操作 | 必须证据 |
|---|---|---|
| UX01 | 新建项目、实际浏览器上传Excel | 后端真实预览与确认；完整文字、行列来源和错误分流 |
| UX02 | 第二次导入原生包和重复Excel | 幂等、冲突提示；当前项目独立，不串另一项目 |

| UX05 | 切换用例内容版本 | 正文和适用脚本正确；历史正文只读；不沿用旧绿色 |

## 9. 实施顺序与完成口径

不用再交一份只有“建议走查”的报告。交接完成后按本设计实施；先做小范围真实路径，再扩满页面，始终单窗口串行写入。

1. 梳理当前用例/脚本/批次/run/媒体关系与旧功能落点，记录不足；同时搭新页面结构，保留原执行内核。
2. 先接用例详情与结果、已有文件包复跑、批次冻结和状态归属。真实后端未就绪时明确阻塞。
3. 接脚本维护、清晰字幕媒体、报告快照与导出；报告格式确认后只实现所选格式的完整链路。
4. 完成UX01–26，删除旧UI专属入口，复核历史兼容及唯一启动路径。

可以分提交，不能分成互不一致的设计版本。结构拆分、接口接线、界面样式各有清楚差异，避免把所有状态与请求继续挤进一个超大文件。无需强制迁移框架或建设新后台平台。

**完成必须给出：** 实际可打开的入口、对应项目/数据配置、已实现与未实现项、真实验收结果、完整受测源码提交、本地HEAD/远端SHA、剩余限制。只有图好看、按钮存在或工程单测通过，不能称整个产品流程完成。
