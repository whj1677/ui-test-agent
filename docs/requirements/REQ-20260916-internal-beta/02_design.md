# REQ-20260916-internal-beta 设计

## 2026-09-17 条件提示与目标命中（DD-2/DD-4增量）

`dismiss_optional`是单个固定动作，不增加通用分支语言；target仅精确role=dialog原文标题，value为原文关闭文字，只读、每步至多一次，禁止repair_anchor/清理。存在性观察最多800ms并受原步骤预算约束；没有匹配节点记录SKIPPED_NOT_PRESENT，但所有原断言仍执行。存在时检查唯一native modal及method=dialog本地关闭表单，无危险输入/确认内容，绑定原DOM按钮与dialog，持久意图后重验，事件捕获守住派发变化；关闭未证实或写请求被拒绝则保留失败，不再点击。

探索仅对当前Case明确授权的上述条件提供opaque dismiss候选，背景仍不可操作，其他提交表单保护不变。method=dialog并不证明任意click/close监听无副作用；不改写被测fetch/storage，沿用网络拒写，不声称防御所有本地状态副作用。

`unobstructed`在已有原子断言采样中核验目标可见视口区域中心和四个内角，记录坐标/命中关系及modal/inert/透明状态；不扩大为全页、所有像素、未来或持续结果。显式无遮挡义务不可用visible/hidden/count代替；条件提示后必须与后续操作定位（含业务行身份）一致。后续实际点击仍独立接受Playwright可操作性检查。条件事实、跳过与行内目标在中文控制台和统一报告可读，旧事实不改。

## 接口与数据流

### 2026-09-17 行内定位与按缺口修复（本轮实施）

- 固定row/cell协议：唯一原生表格、精确身份列和值、唯一行、唯一内层目标或列；行号不是业务身份。固定DOM解析供观察、探索、动作和原子断言共用；派发前仍检查原DOM节点与原行键。列歧义、重复行/目标、虚拟/合并表格明确拒绝，不选第一个；稳定基础定位保留兼容。
- 结构反馈仅遍历已知协议字段，记录field_path、actual_type、合法格式及提示，保留原候选；不回显任意未知键值，不静默猜改。v2/v3及分段规划共用验证，原三候选预算与审批不变。
- 登录后初始保护页单独记录navigation_start，作为技术事实供后续各例核对原首页前置条件。原菜单点击检查不再依赖URL是否填写；URL仍为选填提示。
- 双向核验复用原oracle_quote/obligation_ids与独立模型审查；每条断言必须被审查引用。窄规则拦截原文未要求的行数、非原文行身份、整表数值代替指定行字段。规则和模型都不能证明任意自然语言等价，仍需最终计划批准。
- 恢复只持久化与缺口相关的新增定位事实或唯一可见的相关探测；无关导航/文本变化不触发重规划。已试动作/探测跨轮保留；结构缺陷不转无目的浏览，能力缺口不交给无法扩展协议的适配源码修复。相关事实增量不等于业务验收成功。

### 2026-09-17 登录/菜单与选填入口续作

- 认证导航候选包含实际按钮和角色名称，排除隐藏图标；重复的页面标题不影响角色限定后的唯一性核验。保持同源、无登录挑战、正向退出登录标志和连续3次稳定观测。出站等候会重置稳定样本。
- 控件采集用去装饰的名称提示，尊重aria-labelledby/aria-label；这不是完整可访问名称规范实现，最终仍由Playwright唯一匹配与原DOM句柄身份独立验证。不支持的真实按钮/链接定位保留缺口，不静默丢弃。
- 页面入口作为用户hint单独记录，不伪装为source-confirmed Handoff。JSON字段page_entry_url，CSV/Excel从原始行选填列投影，原业务步骤保持。URL安全检查在请求前，模型不接收未经核验的原始hint，合格实际观察才增加页面证据；入口跳转与回到首页都计预算。
- 对原文明确的菜单/首页导航，计划不得用直达替代；输入变更使旧计划失效。禁止因入口失败清除网络安全阻断状态。404/失效/登录/相关性不足记具体原因并尝试原首页探索，真实认证丢失或安全阻断保留阻塞。
- 未扩展行内同名控件的定位协议；本轮冻结目录中的两个“查看详情”仍是已知能力缺口，不以修改被测页面或用例掩盖。
- 探索浏览器在Chromium原生Document响应阶段校验301/302/303/307/308的Location，同源只读GET逐跳消耗原有动作/循环预算，跨站及危险路径在后续目标请求前阻断。使用CDP Fetch继续原生响应，不代理重放点击，不改写文档响应，保留Cookie/最终URL/只读CDN资源行为；未知POST和原请求护栏不放宽。该验证限DiscoveryBrowser，不宣称所有执行器的所有网络类型均已覆盖。

### 2026-09-16 自主准备补充（用户已确认实施）

- 新增 `job.kind=prepare`，保持不可变的所选 Case 集；打开/复用 BrowserSession，最多等候登录10分钟，然后连续探索和候选准备。首次识别需要无可见登录/OTP挑战、同源、正向退出登录标志及稳定唯一导航文字；既有人工标志经过重新核验可复用。无法判定保留人工辅助入口，不读取密码，不自动确认原文或批准计划。
- `autonomous-recovery.mjs` 负责缺事实后的重观察、只读定位探测和菜单动作，每用例2轮、每轮6步/45秒；三份候选总预算按确认版本持久化，快照/源码重载不补预算。旧记录保守迁移已花费次数；不重放业务操作。
- `adapter-program/worker/runtime.mjs` 用 Acorn + 默认拒绝的AST解释器处理仅 `locate(element)` 的受限映射源码。没有eval/import/vm/任意Node执行。输入仅控件标量，源≤12KB、AST≤500节点/深度24，Worker3秒/32MB仅用于资源隔离。回归基准、原DOM对象句柄身份、旧控件逐项保留及缺口减少后才启用；失败恢复旧版本，登录owner不重启。任务目录保存源码hash、版本及尝试，不跨站点泛化。
- 首页尚未动作时，未知同源后台POST仍abort，但保留网络缺口并允许独立导航；首动作后未知请求仍保守中止。计划依赖仍缺证据的页面时，`PAGE_EVIDENCE_INCOMPLETE` 阻止批准链路。该策略不自动授予只读契约，也不因模型同意放宽权限。
- 原“不运行中改源码”边界此次仅扩为受限映射程序热换；策略、断言含义、执行协议和凭据处理内核仍不可自改。协议不支持、业务语义不明、越权请求等只记录可解释阻塞，不承诺通用代码自愈。

Kimi只读复核提出登录弹窗关闭误判、残缺请求证据和对象身份循环自证三个反例。前两项增补正向登录标志与程序门禁；对象验证使用独立原DOM句柄而不是重新匹配旧定位，语法默认拒绝及字符串上限由源码核验。延迟请求因果归类暂不扩展：首动作后仍一律保守阻断未知请求。

- 电价试用修复：模型侧单独采用 undici EnvHttpProxyAgent 读取既有代理环境，不设置全局代理、不改变 Chromium 请求路由。服务结束释放模型连接池。诊断新增允许清单内的 network_error_code；控制台按当前探索 job_id 展示被拦路径，查询仍通过既有配置入口精确确认。此变化不自动授权任意 POST，不改变业务预期或人工审批。

- `GET /api/config` 返回真实版本/构建及实例身份；`POST /api/shutdown` 校验CSRF和实例ID，先结束接入，再收尾并释放写锁。
- Store 根据同源任务记录计算未清理影响；Controller 在新任务操作前统一阻断。恢复说明只追加，不覆盖历史收据。
- 普通启动保留排他写锁。显式恢复用维护锁互斥，确认原PID不存在后归档旧锁；新启动在取锁前后均检查维护锁，不自动恢复损坏或权限未知的锁。
- 停止后备份保留任务及证据，拒绝合并目标、目录内递归备份和链接；录像流式复制校验，完整清单最后提交。
- 候选包白名单仅为 src/public/vendor、固定启动维护入口、依赖清单及试用说明；开发治理脚本不影响运行身份。摘要用于完整性核对，不是发行签名。
