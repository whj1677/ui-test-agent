### 有限机制诊断

排序解释已正确生成field=编号、direction=ascending，非法枚举问题不再出现。但源复核把三个义务均改成UNINTERPRETED：正常例要求页面先证明编号字段存在；故障例指出输入只有check名称，缺text/table_order/row_count的语义定义。它还把“恰好3行而非12行”的等价性当成必须额外证明的独立条件。

这暴露新增机制的职责缺陷：复核输入缺少共享断言语义契约，且未将原文解释充分性与页面绑定充分性明确隔离。源解释正确、页面尚未绑定与真正业务歧义，被混入同一UNINTERPRETED结论。冻结后继续让候选规划修复这个源复核结论也无效，形成重复往返。工程注入复核回复无法证明真实模型在这个边界上的行为；当前不能宣称机制修复完成。

下一项应先设计可核验的断言语义目录和结构化复核理由：源审查只评原文与谓词含义；页面字段是否存在、唯一和可操作归TARGET_PENDING_BINDING，由实际运行测量决定。真正原文歧义保持UNINTERPRETED；不得通过“总是SUPPORTED”、忽略未知、增加预算、改原题或新增位置词法来绕过。该设计本轮未实施，必须保留反例和独立表达，不因本次两例失败继续叠局部补丁。
