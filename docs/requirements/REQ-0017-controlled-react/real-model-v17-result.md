# 版本17：查询重置与绝对行位置

## 修改依据

版本16扩量诊断已结束，详见[原始诊断结论](diagnostic-v16-matrix.md)。V06原动作短句“点击重置”被只检查action关键词的规则误挡；V07位置义务被记录存在代替。本批不改原用例、页面、manifest或历史收据。

## 实现与能力边界

- 查询重置必须同时具备当前原步骤的肯定操作/查询语义，以及派发前同一实际节点所属原生GET查询表单事实。复用已有表单检查，原生button reset及JS button在此限定上下文可用；POST、弹窗表单、额外业务按钮、敏感控件、外部表单、重置数据、改名和input reset均拒绝。原探索的native reset协议不扩大。表单属性不是任意JS无副作用的数学证明，既有网络/只读授权边界继续存在。
- table_cells可为原精确key指定position，表示同一次完整DOM表格样本中1起始的数据行位置，不作为定位身份。尾部额外行允许；前插/交换、缺行会报差异，重复键等结构歧义为技术问题。来源只支持当前expected中明确首行/第N行+字母数字记录ID的受限语法，不从数据键名/观察/旁支数字推导。中文一至十、阿拉伯1至999支持；任意自然语言位置尚未实现。
- 原义务有这种绝对位置要求时，完整候选不能仅提供成员或相对顺序断言。未派发错误可按原预算纠正，实际差异和已执行动作不重放。
- 编排增加原ID子集筛选，保留原顺序、组类型及字节核验，账本标注subset_only。未知/重复/空ID拒绝；写入组仍只准备。
- 新Windows worktree检出暴露autocrlf改变11份冻结输入字节；逐一确认Git blob符合原SHA后增加明确LF属性，只归一换行，不改manifest/用例内容。旧失败预检日志保留。
