# Windows 便携程序与授权组件交接

本轮交付分为两个独立工程：`ui-test-agent` 是测试工作台，`D:/01_AI工程/01_工程项目/device-license` 是可被其他 Agent 或桌面程序接入的离线授权组件。DLL 不依赖测试工作台，也不启动网络授权服务。

## 用户流程

1. 解压完整 Windows x64 便携 ZIP，双击 `安装.cmd` 离线核验运行环境，随后双击 `启动.cmd`。
2. 在唯一的 `http://127.0.0.1:4322/workspace/` 页面填写主动提供的显示名称、同意采集，并下载设备申请。申请仅包含产品隔离的主板摘要，不包含原始序列号、MAC、硬盘号、登录密码或模型 Key。
3. 将申请文件交给发行方。发行方使用独立签发工具生成许可证；客户端导入后验签并原子保存。客户包只有公钥和验签组件，没有签发私钥。
4. 以后启动仍重新读取主板并验证签名；同一主板无过期日，不要求每次输入授权。内存、硬盘升级不参与绑定；换主板需要重新签发。许可证文件被删除时可重新导入同一主板的原许可，“永久”不等于文件不可删除。
5. 需要 AI 功能时，用户在自己电脑运行 `配置模型密钥.cmd`，再运行 `启用模型工作台.cmd`。Key 使用当前 Windows 用户的 DPAPI 保存，不进入便携包、聊天或用例报告。软件永久授权不代付模型服务费用。

## 组件接入约定

- 包名 `@offline/device-license`，正式验签由 .NET Framework 托管 `DeviceLicense.dll` 实现。C#/.NET 程序可直接引用 DLL；Node、Python 通过本地 `DeviceLicense.Bridge.exe` 的标准输入/输出调用。它不是可被 ctypes/PInvoke 直接按原生 C ABI 调用的 DLL，不需要授权服务器。
- 客户端固定独立的 `product` 与发行公钥；不能接受许可证自带公钥。签名使用 RSA 3072 位、指数 65537、SHA-256/PKCS#1；跨产品、错主板、未知策略或签名被改均应拒绝。
- DLL 自行采集当前主板，生产接口不允许 Node 传入伪造硬件信息绕过绑定。采集字段缺失或厂家占位值不能降级绑定其他硬件。
- 工作台必须在业务数据初始化、任务恢复及业务接口开放前验签；未激活时同一 4322 只提供激活页面和有限激活接口。不能只在快捷方式或页面按钮上判断。
- 组件发行运行时仅含 Node 适配、`core/`、DLL、本地桥及构建清单；`issuer/`、测试、C# 源码、任何用户数据和密钥不进入客户便携包。签发工具由发行方单独保管。
