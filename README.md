测试人员先阅读 [试用说明](试用说明.md)。当前已补构建身份、同站点未清理数据保护、正常停止、中文环境检查及受控异常恢复；真实模型、干净 Windows 和独立人员验收仍未齐全，不能视为已发布。下文历史结果保留各自版本及验证边界。

面向不同业务项目的测试工作台：导入人工用例 → 核对歧义 → 登录确认一次 → Agent 自动探索页面与弹窗 → 自动生成候选计划 → 集中核对 → 浏览器执行 → 查看事实和离线报告。

2026-09-16 分段检查：默认 single 规划器可生成 `ui-agent-plan/v3`，一个原步骤内可依次操作、检查列表、进入详情再检查；原步骤与预期保留。旧 v2 计划行为不变，实验性 staged 仍只生成 v2。核对页、实时事件、唯一报告和新录像均显示检查点；不同检查点分别观察，不证明同一时刻一致或全过程不变。

## 启动

此电脑依赖已安装，双击 `启动.cmd`。新版控制台默认是 **http://127.0.0.1:4179**，使用独立 `data/v02` 目录。也可以在工程目录运行：

```powershell
npm start
```

新电脑安装需要 Node.js 22+。双击 `安装.cmd` 安装锁定依赖及 Chromium；Excel 导入还需要 Python 3.10+，脚本会创建本目录专用环境并安装固定 openpyxl。维护者也可手工执行：

```powershell
npm ci
npx playwright install chromium
python -m pip install -r requirements-import.txt
```

`启动.cmd` 在后台启动本地服务，并打开控制台；重复点击只复用构建摘要及数据目录相同的实例。旧版或同版本不同源码的服务会被拒绝复用，不强制终止已有会话。正常停止旧服务后再次启动才能加载新版后端，刷新页面不能替代重启。使用 `停止.cmd` 或前台运行时按 Ctrl+C 正常收尾。端口可通过 `UI_AGENT_PORT` 设置，数据目录通过 `UI_AGENT_DATA_DIR` 设置。异常退出后可用 `恢复启动.cmd`：只在原 PID 不存在时归档旧锁，保留全部任务及未清理状态。损坏锁、进程权限未知或维护自身异常退出需人工排查。旧4177/4178记录保留，不与新版共写。

实验性开关 `UI_AGENT_PLANNING=staged`：把候选计划生成从单次模型调用拆为骨架、逐步动作、逐步断言三段局部调用，组装后仍走原有结构校验、独立语义核验和人工批准，安全约束不变。每个候选约 1+2×步骤数次调用，计入原批次 100 次上限；诊断日志以 `plan_scaffold`/`plan_actions`/`plan_assertions` 阶段记录失败点，`/api/config` 的 `planning_mode` 显示当前模式。缺省仍为单次调用。程序回归只证明协议连通，真实 DeepSeek 下是否提高有效计划率需在冻结用例集上另行对照复测，不能据模拟结果宣称收益。

## 先体验，无需密钥

1. 点击“体验跨业务演示”，建立本机合成站点及两条演示用例。
2. 展开“辅助操作与单步准备”，点击“打开浏览器”，在出现的 Chromium 窗口点击“进入演示”。演示使用预制计划，不走需要 Key 的自动准备。
3. 点击“确认登录状态”，选择“演示用户”并确认。
4. 勾选两条用例，点击“核对所选计划”，检查查询、创建及精确删除动作，确认。
5. 点击“执行所选”，查看实时活动、用例证据和“下载离线报告”。

演示使用预制计划，不调用 DeepSeek，不代表模型规划已经验证。演示站点的数据在内存中，服务退出后消失；重新体验请创建新演示轮次，旧结果仍可查看。

## 接入自己的项目

1. 在“DeepSeek 连接设置”输入官方 API Key，点击“测试连接”。密钥只保留在本地服务内存，输入框随后清空；也支持 `DEEPSEEK_API_KEY` 环境变量。不会把密钥写入任务、日志或报告。服务重启后需重新配置。
2. 导入 Excel/CSV/JSON 和非生产环境地址，填写本轮授权。浏览器执行无需源码；可选关联用例驱动的前端 Handoff。Excel/CSV 可加选填列 `页面入口URL`（JSON：`page_entry_url`），或导入后在用例详情补填；仅接受安全的同站点入口。留空仍自主探索，有入口先采证再恢复首页核对原导航，不能替代业务步骤。详见 [入口填写说明](试用说明.md#页面入口-url选填)。
3. 选择用例进行模型文本审查。原文与用户补充分开保存；有问题的用例点标题修改“确认操作/确认预期”，记录依据。逐项核对可编辑的预期分项：草稿按标点拆分，不代表模型理解正确；分项不得遗漏原文。其他用例可继续，也可集中核对。

   如果步骤与测试数据矛盾，可在详情的测试数据更正框补充已有 `data/test_data` 字段。原始基线不改动；有效用例采用显式补充。Agent 只能提出有原文引用的问题，不替操作者选择业务预期。
4. 勾选本次用例，点击“开始准备所选用例”，在打开的 Chromium 中登录一次。停在主界面即可，不必手工进入业务模块。服务观察同源界面、登录挑战消失及正向登录后标志，识别后自动继续；最长等候10分钟，可随时停止。无法可靠识别、无登录网站或复杂认证时，使用“辅助操作”中的人工标志入口，不能仅靠隐藏登录框或页面标题判定登录成功。
5. Agent 自动寻找所选用例相关菜单、页面与弹窗；计划遇到技术阻塞时重新观察、探测唯一性、补充页面证据再试。可修复受限的控件映射源码，经语法白名单、回归及原DOM节点身份校验后启用，保留版本和失败记录，不关闭登录窗口。未确认用例先保存探索事实，仍需核对原文。辅助入口保留，但不是正常流程的逐项必点步骤。
6. 核对候选计划是否覆盖所有原预期、输入是否准确、清理是否只作用于授权测试数据，可一次确认多个计划。自动探索不会批准计划或修改业务预期；程序格式检查不能证明业务语义完整。需要仅重新规划时使用“重新规划所选用例”。
7. 执行所选计划。步骤、操作目标、断言观测、定位修复和清理过程持续显示在下方。停止后不再启动新步骤，已授权的清理仍尝试执行。
8. 查看用例详情、截图、视频和离线 HTML 报告。已经发生业务操作的用例复测须新建轮次；不会覆盖历史执行。仅登录失效或前置阻塞、且没有任何操作的用例，恢复后可继续，最多启动5次。

模型会收到你主动导入的用例、确认文本、采集的页面文字/控件和可选导出物。资料需要适合发送到官方 DeepSeek；程序进行有限的明显凭据脱敏，但不是完整的数据分类系统。登录页面不采集内容，密码操作不交给模型，登录过程不录像。用例截图和视频可能包含业务数据，保存在本地。

探索复用同一浏览器里的认证，新建可见探索上下文，结束后保留原登录窗口。它只选择当前观察到的导航候选，允许打开表单以观察字段，不填写、保存、提交或删除数据。即使本轮允许业务写入，探索上下文仍按只读规则拦截请求；查询 POST 需事先配置精确只读路径。源码入口只取已绑定当前 Case 的已确认技术事实，不凭空猜路由。

模型连接采用 `HTTPS_PROXY` / `HTTP_PROXY` 及 `NO_PROXY`（也支持小写变量）；只影响模型请求，不改变业务浏览器或本机控制台的网络路径。启动前设置，修改后正常重启生效。未配置代理时保持直连，HTTPS 证书校验和禁止重定向仍有效。“已配置”只表示已有 Key，以“测试连接”的实际返回为准。连接失败的诊断只记录允许的网络错误码，不保存原始异常中的凭据或代理地址。

探索若被 POST 拦截，状态区显示本次被拦的完整接口路径。核实接口确为查询后，在“环境设置 → 使用 POST 的只读查询接口”逐条填写；不可仅凭接口名字猜测只读，也不可把保存、删除接口放入该列表。勾选计划写入授权不会自动放开探索阶段的 POST。

探索按用例分段，整批最多 24 次探索模型调用、48 次浏览器导航/操作、180 秒，每 Case 最多 12 次候选操作；自动规划也受该批次截止时间和原 100 次逻辑模型调用上限约束。达到预算、找不到入口或缺少技术事实会留下具体原因，不无限重试。界面持续显示当前 Case、目标、页面和阶段；探索事实最多保留最近 128 个快照，不代表整个网站已覆盖。

自主恢复另有限额：同一确认版本累计最多3份候选（换快照不重置）；每用例最多2轮重新采证，每轮最多6步/45秒；每任务最多2次适配源码修复。失败历史、旧候选和源码版本保留，重启不会补回已消耗预算。仅旧记录升级时保守继承已调用次数，不覆盖失败结果。修复源码由受限AST解释器处理，不作为Node/Playwright任意脚本执行；不支持的底层协议仍需维护者升级，不承诺自动修复所有程序缺陷。

首页初始化的未知同源后台POST仍被阻止，但不妨碍观察独立菜单；请求缺失会随页面证据保留。计划若依赖仍有请求缺口的已观测页面，程序阻止生成可批准版本，不能以“空数据”推断业务结果。首次动作之后出现的未知请求仍按保守策略中止该探索；不猜测延迟请求的业务语义。

## 诊断日志与后续优化

在轮次右上角点击“诊断日志”，按 Case、记录类型和处理结果筛选，展开每条记录查看详情；“导出本轮日志 JSON”下载本机已留档的完整集合，不只导出当前筛选页。

日志记录模型请求及提示/输入摘要、脱敏后的发送输入、逐次 HTTP 耗时与重试、模型及 Token 用量、收到的模型回复、解析失败以及程序对探索/计划/修复的处理结论。用 request_id 串起一次模型调用，用 job_id 与 case_id 连接批次和用例；探索记录候选和操作前后事件，业务动作、断言、修复和清理仍以独立执行事实为准。ACCEPTED 只表示程序接纳该结构化提议，不等于计划已经人工批准或产品验收。

日志写到 `data/v02/tasks/<轮次ID>/diagnostics/`，逐条追加并校验摘要链；模型请求前日志无法保存时不发请求，后续写入失败时停止继续请求。日志不包含模型隐藏思考过程；凭据字段与已知 Key 会脱敏，长文本会明确标记截断，缺失的 Token 用量保留未知。日志仍可能包含业务文字，需要在获准范围内分享，不会自动上传到 Agent Lightning。

旧服务进程继续复用已有会话。刷新页面可以查看基础事件，但无法补录历史模型原始回复；正常停止旧服务并再次启动后启用自动探索与详细日志。Key 和浏览器认证保存在内存，服务重启后需重新配置/登录一次；同一次服务会话中的用例继续复用认证。日志摘要用于发现意外修改，不是抵抗本地管理员重写全部文件的签名系统。

优化先依据失败记录分类，固定用例、预期及评估集后比较候选提示的有效计划率、实际断言、清理结果、调用量和耗时；不得只奖励“不再阻塞”。Agent Lightning 仍是独立、可选的提示优化入口，候选不会自动应用到当前任务。

用例详情中的“反馈并重新生成一次”只修订未执行计划，保留原用例与旧候选，每条最多一次；修订后需重新核对。支持“重新校验已有模型回复”，使用摘要链已验证的原回复检查当前格式和原用例，不额外调用模型、不自动批准执行。已执行用例不能使用这两个入口改写历史。

新计划在用例详情和同一份报告中显示输入审查、每轮自修复原因、计划摘要、核验问题与修复次数；完整模型回复仍在诊断日志。新候选批准及执行要求核验记录绑定当前用例、技术资料和计划摘要，重校验旧回复不能绕过这个条件。最多生成三个候选；停止或中断前已预留的候选次数仍计入预算。只有实际用例、技术事实或有界人工反馈改变才开始新预算，旧记录保留。

自动核验同样可能误判，不能证明业务语义正确；源码和页面观察也不定义业务预期。运行中的定位修复继续只替换尚未派发动作的定位，并核实同一对象。发生可能写入后的错误不自动重放整条用例，不改被测系统、不放宽预期、不自动处理未经授权的数据。日志脱敏按对象处理，包含引号或凭据样式的旧候选不会破坏后续请求 JSON。

## 输入格式

- Excel：支持 `.xlsx/.xlsm`，识别中文表头如“用例编号、用例标题、前置条件、测试步骤/操作步骤、预期结果”。普通多工作表文件请指定工作表并分轮导入；不是默认执行所有工作表。原文件也保存在轮次目录。
- CSV：UTF-8、同样的表头，复杂单元格按CSV规则加引号。
- JSON：支持下例或现有便携导入器的 `case-import.json`。每条原用例与步骤ID必须唯一；原预期可以缺失，但确认后才能生成可运行计划。
- 单文件上限12MB，每轮最多500条，单个批次最多100条。首版不从嵌入图片中自动恢复文字规则。缺失/矛盾需确认，不自动补造。

```json
{
  "cases": [{
    "case_id": "SEARCH-001",
    "title": "按名称查询",
    "source_side": "ui",
    "preconditions": "列表内存在目标记录。",
    "steps": [{
      "step_id": "S1",
      "action": "输入目标名称并点击查询。",
      "expected": "只显示名称匹配的记录。",
      "requires_click": true
    }]
  }]
}
```

前端导出物支持用例驱动的 `manual_case_frontend_handoff` 1.0。先下载本轮“用例基线”，让导出方绑定该文件，再关联 JSON。程序校验格式、摘要和基线；没有直接访问源码目录，因此不会把导出方声明等同于本机源码核验。正式需求交接 schema 2.1 不由这个入口直接消费。

## 首版能力与限制

| 项目 | 当前行为 |
| --- | --- |
| 页面 | 标准 HTML/DOM；React/Vue等正常DOM页面与Hash路由；唯一 role/label/placeholder/testid/稳定ID定位 |
| 自动探索 | 登录确认后按用例观察、选择当前候选、导航、观察弹窗；有界循环及超时；自动形成候选计划，保留人工计划核对 |
| 动作 | 点击、输入、选择、勾选、按有限按键、悬停、同源导航、整页刷新、状态等待 |
| 断言 | 可见/隐藏、文本/包含、输入值/选项显示标签、节点数/表格数据行数、勾选/启用状态、数值；必须覆盖全部已确认分项；同一步在一次DOM采样中同时满足，预算从最后操作完成起计算 |
| 前置条件 | 先在不录像的会话验证，执行业务前再次验证；没有准备好不计业务执行 |
| 会话 | 同一轮保持可见登录窗口，Cookie/localStorage/sessionStorage在内存复用；逐用例创建录像上下文 |
| 定位修复 | 只读Case最多2次请求，仅动作发出前的定位失败；补丁限当前失败动作，必须仍对应批准的唯一锚点；保持当前页面，成功操作不重跑。I/O、断言、已发出的动作和清理失败不触发修复 |
| 写入 | 非生产确认；写计划需明确授权和清理方案。执行上下文拦截未授权非GET请求；查询POST需配置精确只读路径 |
| 记录 | 原用例、确认及计划历史；动作发出前保存不可覆盖意图，事后封存事实和事件摘要；任务状态可用于进度，不能替代执行事实 |
| 清理 | 先观察是否已恢复，再核对批准的资源身份；清理意图保存失败不执行删除；未知/失败保留待清理状态 |
| 报告 | 校验事实生成统计；最新冻结批次的原Case为分母；业务/清理/证据独立显示，缺失媒体输出PARTIAL并保留可用内容；媒体上限150MB |

当前不支持 Canvas 纯视觉操作、跨域 iframe、多账号协同、原生桌面/硬件、文件上传下载断言、浏览器原生确认框、WebSocket，以及无法通过上述断言表达的复杂计算。持续性、动作中间态和跨步骤计时不能被转换为普通同时状态断言。复杂自定义表格/Shadow DOM/SSO/IndexedDB认证尚未验证。前端源码可以补充技术事实，但不能定义需求。

网络方法拦截不能证明所有GET都无副作用，也不是操作系统安全沙箱；同源边界不能代替测试账户和测试数据隔离。创建、修改、删除及清理的对象归属仍需核对计划。纯文本模糊用例不会自动变成可靠预期。

## 结果怎么读

“已核对断言满足”只说明这份已确认计划的断言得到满足，不自动宣称产品验收。“断言不一致”保留实际值，仍需区分产品问题与计划语义问题。自动化失败、数据不足、登录失效、写入阻断、清理失败分别列示。

新版报告以最近一次冻结的所选原Case为分母，每次尝试保留，不把修复数当覆盖率。旧数据没有冻结批次时明确按原基线展示。业务断言满足、清理失败和媒体不全可以同时存在，不应相加。事实、事件和媒体读取时核对摘要；发现未封存意图或未索引事实时标为证据待核实，不自动恢复为成功。摘要用于发现意外修改，不是抵抗本地管理员改文件与摘要的签名系统。

v1计划只供历史查阅，不能沿用旧批准执行；需重新确认预期分项、生成和批准当前计划。现在同数据目录、同站点的未清理影响会阻止新任务，异常退出可受控恢复进程锁；跨数据目录/跨工作站保护、任意损坏恢复和跨角色执行仍不支持。自动探索受上述 DOM、动作和预算范围限制，本轮未承诺实现详细设计的全部建议项。

## 真实 DeepSeek 与提示优化

按用例探索会记录目标步骤、已观察控件及其页面状态、进入路径，并区分 DOM 观察、源码确认候选、源码推断和未解决信息。重复的同状态／同动作／同值不会继续作为候选；不同表单状态与输入值分别记录。生成计划只使用该用例最新探索批次的页面，历史事实仍留档。

需要通过输入或选择选项了解页面时，可在用例工作区点击“导入探索交互说明”。该 JSON 由前端技术审查人员提供，与本轮用例基线绑定，声明具体 Case、页面路径、控件、操作、有限值及无业务写入的源码依据；模型不能扩大声明。没有这份可选说明时，仍可导航和打开页面，但不会增加输入／选择候选。对依靠 input/change 自动保存、改变本地业务存储或存在不明确副作用的控件，不应声明可探索；网络拦截不能证明任意页面 JavaScript 都无副作用。技术格式见 [探索交互说明](docs/discovery-interactions.md)。

2026-09-16 探索增强配对试验：10 条冻结样本各生成一次真实 DeepSeek 计划，零反馈；增强前 3/10、增强后 4/10 经独立审查与主管核对后执行，7 次执行的断言均满足，录像和清理证据已验证。198 项程序回归达到断言。调用次数 32 → 49，总 Token 778443 → 2493525；多出的合格计划没有新增页面采集，另有一个探索中断样本，尚未证明稳定收益。查看 [探索对照统一报告](../work/discovery-pilot-20260916/统一探索对照报告.html)。输入/下拉探索只在导入经过技术审查的交互说明后启用；程序能力验证不等于真实业务验收。
